# MnemoWeave 文档

本目录保留六份核心文档，描述**当前仓库真实实现**与已确定的目标态。历史材料、ADR 编号体系与逐批决策台账已移除；影响当前实现的决策以结论形式并入 `architecture.md` 的决策表。

## 文档清单

| 文档 | 回答的问题 |
|---|---|
| `architecture.md` | 系统是什么、由哪些包组成、数据归谁、如何部署、安全边界在哪、哪些设计选择已由代码固定 |
| `implementation.md` | 契约长什么样：HTTP 路由、MCP 工具、Provider CLI 调用、治理库 schema 与迁移、状态机、运行时记忆、配置项 |
| `sync.md` | 三机共享记忆：条目模型与 Revision、同步范围与游标、版本与变更规则、端点、写入与应用、授权矩阵、故障恢复、保留策略 |
| `dsh-ui.md` | DSH 记忆界面的实现、安装、验证方式与缺口（可查看与编辑） |
| `host-acceptance.md` | 三个目标 Host 的接入现状与真实会话验收步骤 |
| `status.md` | 最近一次验证实际跑了什么、结果如何、还剩哪些未完成或阻塞项 |

## 权威顺序

1. **代码与测试**是唯一事实来源。本文档与代码冲突时，以代码为准，并立即修正文档。
2. 本文档中的「已实现」必须能指向具体路径或测试文件；指向不了的只能写「规格」或「未决」。

## 状态标记

| 标记 | 含义 |
|---|---|
| 已实现 | 有源码路径与测试证据 |
| 规格 | 契约或设计已定义，代码可能只实现了一部分 |
| 未决 | 尚未选择，禁止在实现中自行填默认值 |
| 未验收 | 有代码，但没有真实环境证据（真实桌面会话、真实设备、远端部署等） |

## 维护规则

- 改契约、状态机或迁移时，同一提交内更新 `implementation.md` 与 `status.md`。
- 新增未决项写入 `status.md` 的「未决事项」，不在正文里悄悄定默认值。
- 测试数字只能写实际跑出来的结果，并注明运行日期与命令；没跑或失败的检查不得写成通过。
- 文档中不写本机绝对路径以外的个人数据、令牌或记忆内容。
