# 三、R2：核心组件架构

## R2-1：核心组件组织方式

**最终选择：方案 B**

保留 Source、Strategy、Enhancement、View 的核心抽象，重新组织为 Mneme 自己的核心组件体系。

不简单照搬 dsh-mnemon 的实现，也不完全重新发明一套抽象。

重点是明确：

- 组件注册。
- 组件能力声明。
- Strategy 组合。
- View 生成与校验。
- 统一执行机制。

## R2-2：底层 Pipeline

**最终选择：采用 Pipeline 作为执行机制**

Pipeline 作为可复用的底层执行机制。

用于组织多阶段任务，例如：
- Recall。
- Remember。
- Candidate 审核。
- 正式记忆写入。
- Projection 更新。
- 后台知识整理。

Pipeline 不取代 Strategy，也不取代 Application Core。
