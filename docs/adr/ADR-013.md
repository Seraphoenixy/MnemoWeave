# 八、R7：View 架构

## R7-1：View 结构

**最终选择：方案 B**

采用结构化 View。

View 不只是拼接后的自然语言提示词，而是承载本轮运行时上下文的结构化对象。

应能够表达：
- 记忆内容。
- 来源。
- 作用域。
- 优先级。
- 适用条件。
- 授权信息。
- 上下文预算。
- 相关元数据。

## R7-2：Grants

**最终选择：strict**

采用严格授权机制。

组件和 Host 必须在授权范围内执行操作。

不允许仅凭提示词或模型自我判断决定是否具有权限。

## R7-3：View 更新机制

**最终选择：immutable**

View 一经生成即不可变。

需要更新时，重新生成新的 View，而不是原地修改已经交付给工作模型的上下文。

这样便于追溯、验证和保证本轮执行的一致性。
