# 九、R8：记忆组织和 Runtime

## R8-1：长期记忆沉淀架构

**最终选择：方案 B——候选记忆层，审核后写入 Mnemon**

正式记忆不直接接受所有来源的原始写入。

先形成 Candidate Memory，再经过审核和治理，最终写入 Mnemon。

这样可以将工作事件、记忆提炼和正式知识存储分离。

## R8-2：Runtime 组织方式

**最终选择：方案 C——Pinned + Dynamic Projection 混合**

Runtime 由两部分构成：

1. Pinned Memory：明确固定、需要持续注入的记忆。
2. Dynamic Projection：根据当前项目、Host、Session 和任务动态生成的上下文投影。

Pinned 保证重要上下文稳定存在。

Dynamic Projection 保证记忆能够随着当前工作变化。

## R8-3：Session 事件保留策略

**最终选择：方案 B——限期归档，重要事件长期保留**

Session 事件采用分层保留策略：

- 热数据：近期活动和当前任务需要的数据。
- 限期归档：具有一定参考价值但不需要永久保存的历史事件。
- 长期保留：具有重要工程价值、技术决策价值和复用价值的事件。

不采用无限期保存全部原始消息的方式。

## R8-4：长期记忆分类方式

**最终选择：方案 B——统一记忆库，按知识类型分类**

采用统一记忆库，不为每种知识类型建立独立的物理记忆数据库。

通过以下机制组织：

- 知识类型。
- 实体。
- 标签。
- 关系。
- 作用域。

项目、技术领域和平台通过实体及标签组织，而不是将每个领域强制拆成独立记忆库。
