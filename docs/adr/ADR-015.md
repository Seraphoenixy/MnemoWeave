### ADR-015：R9 审核与冲突处理

- 审核机制：方案 B。
- 记忆冲突处理：方案 C。

## 自动审核为主、异常人工介入

Candidate 在正式写入 Mnemon 前，由确定性规则和 LLM 语义检查共同完成质量检查：

| 维度 | 要求 |
|---|---|
| 来源证据 | 明确来源，能够追溯原消息、工具事件或其他证据 |
| 准确性 | 无明显事实/逻辑错误，识别未经证实的推断 |
| 复用价值 | 具有跨任务、会话或未来工程实践的复用价值 |
| 适用范围 | 明确项目、技术栈、版本、环境、前置条件 |
| 重复性 | 检查已有记忆，考虑关联或补充 |
| 一致性 | 不与已有记忆、技术约束、已确认架构决策冲突 |

所有必要检查满足才自动批准；明确无价值、明显重复或不可接受质量问题自动拒绝。事实不确定、来源不足、潜在冲突、适用范围不明或模型无法判断时转人工。无法判断绝不默认通过。

人工重点处理真实技术争议、重要工程经验/架构决策、跨项目抽象和 Global 晋升、影响重要记忆的替代，以及自动审核不能确定范围或真实性的情况。结果为批准、拒绝、修改后重新审核；保留完整操作记录。

审核通过不等于写入成功：质量检查 → 审核结论 → 正式写入任务 → Transactional Outbox → 稳定幂等键 → Execution Receipt 与 Provider 结果核对 → 已持久化。允许失败重试，不得因重复执行产生重复正式记忆。

候选生命周期至少包含 Pending、Approved、Rejected、Persisting、Persisted、Failed；正式记忆的替代状态另行管理。

## 保留历史，通过版本和替代关系更新

- 事实自然演变：同一逻辑记忆创建不可变 Revision，保留旧版本及证据，更新当前指针，记录变更时间和依据；不删除旧版本。例如 V1.0 升至 V2.0，两者保留适用时间。
- 技术方案替代：保留旧记忆，创建新的独立记忆，建立 Supersedes 关系并记录原因、证据、适用时间；旧方案标记 Superseded，新方案为当前有效方案。
- 条件不同：分别保留项目、版本、环境、前置条件，通过标签、实体、关系关联；不得仅凭表述不同判定冲突。例如 ARM 与 PowerPC 适用条件不同。
- 同条件下真实矛盾：暂停自动通过和正式写入，保留双方原始记忆/证据，标记冲突，生成冲突审核任务，交人工判断。不得按时间或模型置信度自动覆盖。
- 人工解决后：正确方继续有效；被替代方保留历史并建立替代关系；双方成立则补充条件并保留；双方缺证则保持待验证，不晋升确定结论。

R17-4：不可变版本 + 当前指针；R19-6：独立记忆 + 显式关系；R19-7：Outbox + 幂等 + Receipt；R19-8：时间/事件双触发复核。必须区分同一逻辑记忆 Revision 与不同逻辑记忆之间的替代/矛盾/派生；不能全部简单覆盖或全部当作独立实体。

## 理由与约束

自动为主减少普通沉淀的人工负担，异常保持人工控制；保留历史维护工程背景、时间性、版本和适用条件。

自动审核不代替真实技术验证；LLM 置信度不能单独证明正确；未审核候选不得进入正式库；不得直接覆盖或物理删除有历史价值的记忆。版本、状态、关系和人工处理可追溯。跨 Provider 写入必须幂等并核对结果。

# 十、R9：审核与冲突处理

## R9-1：审核机制

**最终选择：方案 B——自动审核，异常候选人工介入**

采用自动审核为主、人工审核为辅的方式。

普通候选记忆通过规则和语义检查后可以自动审核通过。

存在以下情况时需要人工介入：

- 来源证据不足。
- 内容存在不确定性。
- 与已有记忆发生冲突。
- 涉及重要工程决策。
- 跨项目抽象或晋升 Global。
- 自动审核无法判断其正确性和适用范围。

审核通过和正式写入是两个独立阶段。

正式写入必须经过可靠任务流程，并记录执行结果。

## R9-2：冲突处理

**最终选择：方案 C——保留历史，通过版本和替代关系更新**

不直接覆盖或删除已有正式记忆。

根据冲突性质分别处理：

- 同一知识的演变：创建新版本，保留旧版本。
- 新方案替代旧方案：建立 Supersedes 关系。
- 适用条件不同：同时保留，明确适用范围。
- 真实事实冲突：保留双方，标记冲突，等待验证或人工处理。

Recall 默认优先返回当前有效记忆，但允许根据查询需要获取历史版本。
