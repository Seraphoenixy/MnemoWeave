# 十四、R13：任务执行与可靠性

## R13-1：Task / Pipeline Run / Execution Receipt 关系

**最终选择：方案 B——三者独立，建立关联**

三者具有不同职责：

- Task：业务任务及其生命周期。
- Pipeline Run：一次具体的 Pipeline 执行。
- Execution Receipt：外部操作的执行凭据和结果记录。

三者不能合并为一张简单任务表。

## R13-2：数据库事务与任务入队

**最终选择：方案 B——Transactional Enqueue**

业务数据变更和任务入队需要在同一数据库事务中完成。

避免业务状态已经提交，但任务没有成功进入队列。

## R13-3：外部操作幂等性

**最终选择：方案 B——稳定幂等键 + Receipt + 结果核对**

外部操作必须具有稳定幂等标识。

执行前后通过 Receipt 和 Provider 结果核对判断操作状态。

不能因为请求超时就假设 Provider 没有执行成功。

## R13-4：任务暂停、取消和人工介入

**最终选择：方案 B——显式控制状态 + 检查点恢复**

任务支持：

- 暂停。
- 恢复。
- 取消。
- 检查点。
- 人工介入。

恢复任务时从最近有效检查点继续执行，并核对外部操作状态。
