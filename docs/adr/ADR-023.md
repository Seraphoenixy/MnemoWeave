# 十八、R17：记忆历史与容量治理

## R17-1：Session 原始数据保留策略

**最终选择：方案 B——热数据 + 限期归档 + 重要事件长期保留**

Session 原始事件采用分层保留。

近期活跃数据保留在热存储中。

一般历史事件限期归档。

具有长期工程价值的重要事件允许长期保留。

## R17-2：Candidate Memory 生命周期

**最终选择：方案 B——保留审核记录，按状态清理候选内容**

保留候选记忆的审核记录和必要元数据。

根据候选状态及其生命周期清理不再需要的内容。

不得因为清理候选正文而丢失重要审核历史。

## R17-3：长期记忆自动维护

**最终选择：方案 B——后台自动分析，形成候选治理操作**

后台定期分析长期记忆。

可以形成以下候选治理操作：

- 过时识别。
- 重复识别。
- 冲突识别。
- 合并建议。
- 替代建议。
- 重新验证建议。

后台自动分析不直接绕过审核和治理流程。

## R17-4：长期记忆版本与历史保留

**最终选择：方案 B——不可变版本 + 当前版本指针**

正式记忆采用不可变版本。

更新时创建新版本，并更新当前版本指针。

历史版本保留，以支持追溯和历史 Recall。

## R17-5：本地副本变更与删除传播

**最终选择：方案 C——增量变更流 + 定期全量校验**

通过增量变更流同步远端数据变更。

定期执行全量校验，发现不一致时进行修复。

支持记忆更新、删除、替代、归档等状态传播。

## R17-6：存储容量预算与自动清理

**最终选择：方案 B——软限制 + 硬限制 + 优先级清理**

设置软容量限制和硬容量限制。

达到软限制后触发清理建议或自动维护。

达到硬限制时限制非关键数据继续增长。

按照数据优先级清理，而不是简单按照文件创建时间删除。
