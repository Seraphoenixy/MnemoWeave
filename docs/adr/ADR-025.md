# 二十、R19：记忆沉淀和知识治理

## R19-1：Remember 输入来源与触发机制

**最终选择：方案 B——显式 Remember + 工作事件触发**

两种入口：

- 工作模型主动 Remember。
- 工作事件触发后台整理。

事件只提供候选知识素材，不直接进入正式记忆。

## R19-2：工程知识分类体系

**最终选择：方案 C——固定一级类型 + 自由标签 + 实体关系**

采用固定一级知识类型：

- Concept：技术原理。
- Practice：工程实践。
- Architecture：架构决策。
- Troubleshooting：故障案例。
- Constraint：技术约束。
- Procedure：操作流程。
- Reference：技术参考。

在此基础上允许自由标签和实体关系扩展。

## R19-3：跨项目知识抽象与复用

**最终选择：方案 C——生成抽象候选，审核后晋升 Global**

跨项目知识不能简单复制或直接提升为 Global。

先提炼具有通用价值的抽象候选。

审核其通用性、适用范围、证据和限制条件后，再晋升 Global。

保留原始项目记忆及来源关系。

## R19-4：记忆来源、证据与可信度

**最终选择：方案 B——结构化 Provenance + 可信度信息**

每条重要记忆应具有结构化来源和证据。

包括：

- Source。
- Source Reference。
- Evidence。
- Verification Status。
- Confidence。
- Applicability。
- Limitations。
- Last Verified。

模型自评置信度不能替代真实工程验证。

## R19-5：Candidate Memory 质量检查

**最终选择：方案 C——规则检查 + LLM 语义检查**

规则检查负责确定性验证。

LLM 负责语义层面检查：

- 内容是否完整。
- 是否存在歧义。
- 是否缺少必要适用条件。
- 是否存在潜在矛盾。
- 是否具有长期保存价值。

两者共同形成审核建议。

## R19-6：记忆冲突与合并数据模型

**最终选择：方案 B——独立记忆 + 显式关系**

冲突双方首先作为独立记忆保存。

通过明确关系表达：

- Supports。
- Contradicts。
- Supersedes。
- Refines。
- DuplicateOf。
- DerivedFrom。
- RelatedTo。

合并时产生新候选，不直接覆盖已有正式记忆。

## R19-7：正式记忆写入与审核流程

**最终选择：方案 B——Transactional Outbox + 幂等写入 + Receipt**

审核通过后，将正式写入任务放入 Transactional Outbox。

通过稳定幂等键执行 Provider 写入。

使用 Receipt 记录操作及结果。

写入成功后确认持久化状态。

发生超时或失败时，通过结果核对确定是否已经执行，避免重复写入。

## R19-8：知识过时识别与重新验证

**最终选择：方案 C——时间 + 事件双重触发**

根据知识的时间特征和外部事件触发重新验证。

例如：

- 软件版本变化。
- 项目架构变化。
- 技术方案被替代。
- 外部技术规范更新。
- 关键硬件平台变化。
- 长期未验证的技术结论。

知识重新验证状态包括：

- Valid。
- ReviewDue。
- SuspectedStale。
- Superseded。
- Invalidated。

重新验证不等于直接失效。
