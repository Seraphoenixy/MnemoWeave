### 健康检查

打开记忆系统的“状态”页。使用 Mnemon Native 时再检查它的二进制，其他 Provider 不需要：

```sh
command -v mnemon
mnemon --version
```

Windows PowerShell：

```powershell
Get-Command mnemon -ErrorAction SilentlyContinue
Test-Path "$env:LOCALAPPDATA\Programs\mnemon\mnemon.exe"
```

```text
/mnemon status
```

<a id="ops-版本检查与更新"></a>

### 版本检查与更新

状态页的“检查版本”打开“检查与更新版本”面板：

- **MnemoWeave 主插件**：状态页显示正在运行的构建。当前项目从源码构建并按 [DSH 安装与热重载](usage.md#deepseek-harness)更新。
- **Mnemon CLI**：本地版本来自 `mnemon --version`，最新版本来自官方 `@mnemon-dev/mnemon` npm 包。只有 Mnemon Native 需要它，未安装时显示为可选并给出安装命令。

Mnemon CLI 支持官方 npm 启动器、Homebrew Cask / Formula 与 `go install`。版本面板按实际安装来源给出可用操作。

npm 更新要求当前启动器属于现有 npm 所报告的全局安装目录；不同 Node/npm 环境或启动器故障会显示修复指引。首次安装或迁移使用 `npm install --global @mnemon-dev/mnemon@latest`，后续使用 `mnemon update`。命令在 DSH 宿主运行，需要 Node.js 22+。修改 PATH 或 CLI 配置后，重新检查并核对面板中的可执行文件路径。

在 Windows 桌面宿主中，记忆操作和版本检查会直接调用已识别的官方 Mnemon npm 安装所锁定的原生程序，避免 npm 启动器额外弹出控制台窗口，并保留隐藏子进程、超时、取消和已保存的嵌入设置。界面显示的安装路径和 npm 更新归属仍指向原启动器。对于未知包布局或缺失的原生依赖，继续使用启动器回退路径及其修复诊断。

展开 dsh-mnemo-weave 子包列表，可按 Source、Strategy、Provider 查看版本。主包固定的依赖随主包更新，仅当前所属 Profile 中独立安装的包支持单独更新；源码链接保持原维护方式。包更新串行执行，重新检查或重开面板仍保留待重启提示。只读连接可检查版本与复制命令；页面更新需要管理权限且开启 `writeEnabled`。

Go 更新还要求当前执行文件确实位于本机 Go 的安装输出位置（`GOBIN`，或 `GOPATH` 第一项的 `bin` 目录），且未配置交叉编译目标。不能仅因下载的二进制包含 Go 构建信息就认定它由 Go 管理。CLI 更新后还会核验当前执行文件已达到所检查的版本，才报告成功。

更新命令由 Host 固定选择：浏览器不能传入命令或参数，执行禁用 shell，并限制时间与输出。插件更新在所属 profile 中安装已检查的精确版本，确认实际安装版本后才报告成功，避免固定 beta 版本未变却提示已更新。更新完成后界面自动重新检查两个组件并刷新状态。Mnemon CLI 从下一次调用起生效。主插件的本地构建按 [热重载流程](usage.md#deepseek-harness)生效，宿主报告需要重启时再完全退出并重新打开 DSH。

### 备份与恢复

<a id="ops-推荐设置页-zip"></a>

<a id="ops-推荐插件页-zip"></a>

#### 推荐：设置页 ZIP

记忆系统**设置**页“存储”一节中的“备份与迁移”针对**当前有效根**工作：

- **导出 ZIP**：包含 Runtime、Documents 和全部 Mnemon Native Memory Spaces；三方连接、本地外部 Store 与远程数据不进入包；
- 包中只有 dsh-mnemo-weave 随附的记忆来源：运行时记忆、工作区档案与记忆空间。从其他插件包安装的记忆来源既不会导出也不会导入，它的数据由它自己保存；
- **导入 ZIP**：先预检，再合并到当前有效根；
- 包内包含 `manifest.json`、SHA-256 清单和三类数据摘要；
- 导出与导入持有组件锁，Memory Space 仍有未 checkpoint 的 WAL 时会拒绝；
- 导入检查路径、数量、压缩 / 展开大小、JSON schema、Document 哈希、registry 与 SQLite 头；
- 合并先写 staging，再替换目标组件；提交失败会恢复导入前目录。

当前 UI 只提供安全合并，不做“覆盖一切”：

- Runtime 按目标与内容去重；
- 相同 Document ID + 相同内容跳过，ID 冲突且内容不同则生成新 ID；
- 记忆空间按其中的记忆与关联比较，召回时改写的计数和之后补齐的向量不参与比较。一条关联由它连接的两条记忆及其类型确定：合并空间或重新关联会改写它的权重、备注和时间，值不同的同一条关联仍是同一条关联，保留本机的值。因此在一台设备上改过的权重或备注只留在那台设备上。记忆的更新时间也不参与比较：嵌入服务恢复响应后用嵌入设置里的**补齐**或 `mnemon embed` 补齐向量，或用 `mnemon gc --keep` 让记忆免于清理，都会改写这个时间，记忆本身并没有变。相同 ID 的空间会并入只有传入版本才有的记忆，因此两台设备都新增了记忆时，结果仍是一个同时包含两边记忆的空间；本机已有的行、召回计数、读取日志和表结构保持不变。同一条记忆在两边不同（一边编辑或遗忘了它）时，传入版本以新 ID 保留在本机版本旁边，只保留一份，它之后的版本会更新这份副本，而不是再添加一份。新 ID 的空间：本机已有同名空间包含其全部记忆时跳过。比较时用 `node:sqlite` 读取数据库（Node 22.13、23.4 及以上）；更早的 Node、无法读取的数据库、含虚拟表的数据库或超过 50 万行的数据库比较字节。

两份各自有效的 MEMORY 文件合并后超过工作记忆上限时，Mnemon 优先保留重要度较高、更新时间较新的条目，同分同时间按文本稳定排序选择。未保留的条目连同时间、分支范围和来源信息，以完整 JSON 记录保存在 `<dataDir>/runtime/archived/import-overflow/`。归档与热记忆一起提交；归档写入失败时保持原数据。重复合并复用已有归档。

安全导入会分别报告本机归档条数与进入热记忆的远端条数。可检查 JSON 文件，在释放空间或提高容量后，通过运行时记忆页面恢复需要的条目。与已有 Runtime 归档一致，该目录只保存在本机，**不包含在 ZIP 中**，完整离线备份应包含它。USER 容量校验、格式错误及单份输入已经超限时的拒绝行为保持不变。


导入受 `writeEnabled` 控制，只读部署会拒绝。ZIP 包含私有记忆，应加密、限制访问并验证恢复。Provider 凭据保存在 `state/memory-providers.json`（`0600`），不会进入 ZIP。已保存的凭据值也不会经管理通道返回；若要备份连接，需要按下述离线快照保护整个 `state/`。

#### 服务器同步

在 GitHub Actions 手动运行 **Build Linux Sync Server** 后，可下载 `MnemoWeave-linux-server` artifact。推送 `v*` 标签也会构建，并将同一份 `tar.gz` 附加到草稿 Release。归档内含 Linux x86_64 版 Node.js 24、同步服务、启动脚本和 systemd 单元。运行环境需要 glibc 2.28 或更高版本，并满足 [Node.js 24 平台要求](https://github.com/nodejs/node/blob/v24.x/BUILDING.md#platform-list)。

将归档里的 `MnemoWeave-linux-x64/` 内容解压到 `/opt/mnemoweave/`。按下面的命令创建验证记录时，将 Node.js 命令替换为 `/opt/mnemoweave/start.sh --init-auth`，并从 `/opt/mnemoweave/mnemoweave-sync.service` 安装 systemd 单元。更新时替换程序文件并重启服务，继续使用现有的验证记录和数据目录。

Linux 服务使用 Node.js 24。构建后可单独复制 `dist/mnemo-weave-sync-server.js` 到服务器，改用 `.mjs` 后缀运行。构建文件包含运行依赖。服务默认监听 `127.0.0.1:4319`，远程客户端通过 HTTPS 反向代理访问。反向代理需转发认证和同步路径，且允许至少 8 MiB 的请求体。

以下命令在部署目录可访问的 Bash 环境中执行。示例 unit 使用 `/usr/bin/node` 和 systemd 247 或更新版本。

```bash
sudo install -d -m 0755 /opt/mnemoweave
sudo install -m 0644 dist/mnemo-weave-sync-server.js /opt/mnemoweave/mnemo-weave-sync-server.mjs
sudo install -d -m 0700 /etc/mnemoweave-sync
sudo -v
read -rs -p 'Sync password: ' sync_password
printf '\n'
printf '%s' "$sync_password" | sudo env MNEMOWEAVE_SYNC_AUTH_FILE=/etc/mnemoweave-sync/auth.json \
  /usr/bin/node /opt/mnemoweave/mnemo-weave-sync-server.mjs --init-auth
unset sync_password
sudo install -m 0644 deploy/linux/mnemoweave-sync.service /etc/systemd/system/mnemoweave-sync.service
sudo systemctl daemon-reload
sudo systemctl enable --now mnemoweave-sync
curl -f http://127.0.0.1:4319/health
```

`--init-auth` 从标准输入读取 8–1024 个 UTF-8 字节的单行同步口令，生成权限为 `0600` 的 SRP 验证记录。已有文件时命令会拒绝覆盖。轮换时先生成到新的文件路径，再替换验证记录并重启服务。systemd 通过 `LoadCredential=` 向服务提供验证记录，SQLite 数据存放在 `/var/lib/mnemoweave-sync`。自行启动时可用 `MNEMOWEAVE_SYNC_DATA_DIR` 指定数据目录，用 `MNEMOWEAVE_SYNC_AUTH_FILE` 指定验证记录，默认读取数据目录下的 `auth.json`。备份数据库时使用 SQLite 在线备份，或停服后复制目录。

旧版使用静态令牌。升级时继续使用原数据目录，生成验证记录，并在同一维护窗口更新服务和客户端。客户端仍可把 `MNEMOWEAVE_SYNC_TOKEN` 的值作为 PAKE 口令使用，优先读取 `MNEMOWEAVE_SYNC_PASSWORD`。新版服务只接受 PAKE 签发的会话令牌。

在各台机器的 **记忆系统 → 设置 → 存储 → 服务器同步** 填写服务器地址和初始化验证记录时使用的同步口令，点击 **验证并保存**，然后点击 **同步全部**。连接存入 DSH 凭据库，保存后口令输入框会清空。DSH 也支持从服务进程读取 `MNEMOWEAVE_SYNC_URL` 和 `MNEMOWEAVE_SYNC_PASSWORD`，已保存的连接优先。

一次操作会同步工作准则、活动记录和所有登记且未排除的工作区记忆，使用全局或自定义存储时共享数据目录只同步一次。各台机器上需要对应的工作区请使用相同的 DSH 工作区名称。同一台机器上的不同工作区使用不同名称。首次接入可先同步持有完整数据的主机。两边都有重要内容时可先导出 ZIP。

工作区范围按**同名等价**合并，不弹冲突提示。DSH 工作区标识由本机绝对路径派生，两台机器上同名工作区必然不同名，因此服务器上只能用名称对应。两边的快照按并集合并：工作准则条目按目标与正文合并，档案按内容合并（同一份记录两边内容不同时各留一份，副本 id 由内容派生，重复同步不再新增），记忆空间按其中的记忆合并。合并结果按稳定顺序规范化，因此合并一次后两台机器产出的快照字节一致，之后的运行不再互相重复推送。共享数据目录（`global`、`custom`）与全局工作准则仍整份替换：一份存储容纳多个工作区，没有可按机器对应的身份，两边同时改动时仍停下来由人选择保留哪份。

档案记录中的工作区路径属于本机，不进入同步快照。拉取后按本机路径重新标注，因此另一台机器的档案不会在档案页留下指向不存在目录的分组。

记忆内容按文件同步。每个范围发布一份清单，列出该范围快照由哪些文件组成、每个文件的 SHA-256，以及整份归档的摘要。运行开始时先读取服务端清单，与本机的文件逐一比对：

- 归档摘要与本机一致时，该范围不做任何传输。
- 上传只发送内容有变化的文件；服务端已按内容摘要存过的文件不会重复上传，因此改一条记忆只上传对应的文件。
- 拉取同样只下载内容不同的文件，其余文件复用本机已有内容，随后在本地按固定顺序和固定时间戳重新组装归档，校验总摘要后，在 Source 写锁内确认本机内容仍与预检一致，再整体替换。

归档是确定性构建的：同样的文件集合总是产出同样的字节，因此总摘要可以端到端校验，部分下载也能在本地补齐成完整快照。活动记录仍按游标追加，只提交尚未确认的事件。

服务端只保留最新清单引用的文件。被替换下来的文件在宽限期后删除，宽限期覆盖「已上传、清单尚未落盘」的并发写入和正在下载旧清单的副本。

单个范围的上限是一个范围 4096 个文件、归档 48 MiB（Pack 传输上限）、单个文件 128 MiB，与 Pack 读取时的单条目上限一致，因此能导出的范围也能同步。拉取时逐文件校验内容摘要与归档总摘要，缺失或摘要不符会在替换前报出具体文件。已有版本按定长分块同步，其状态文件记录的是旧快照形式；升级后该状态按「从未同步」处理并重新发布一次，游标保留，之后的运行恢复为增量。

同步进行时，**服务器同步** 下方显示当前阶段、本次共几步、正在同步的记忆范围、已传输文件数和已用时；同一进程发起的同步在其他窗口也会显示同一行状态，并在此期间禁用地址与口令输入。同步结束后该行改为上一次同步的结果：完成时给出结束时间和拉取、推送数量，失败时给出原因，因快照冲突停止时指出冲突范围。只保留最近一次，宿主重启后清空。进度由宿主进程持有，不写入存储，也不进入 Pack 或同步数据。

**定时自动同步** 默认开启。宿主按所选间隔自行运行同一套同步，间隔从一次运行结束时算起，可选 5、15、30 或 60 分钟，配置项为 `autoSync.enabled` 与 `autoSync.intervalMs`。未保存服务器地址和口令、也未设置相应环境变量时，定时器保持空闲，不发起请求也不记录失败。自动运行与手动点击共用同一把锁，因此不会同时进行两次；运行中再次触发会被拒绝。因快照冲突停止时定时器暂停，在页面选择保留哪份副本后恢复；服务器不可达、口令被拒等其它失败按间隔重试。宿主未运行时不进行同步。

工作台顶栏常驻同步状态指示，与组合状态并列，不必打开设置页即可看到。图标区分已同步、同步中、失败和未配置；悬停显示上次运行的结束时间与拉取、推送数量，失败时显示原因，冲突时指出范围。点击在已配置时立即运行一次同步，未配置时打开设置页。该指示读取的是宿主同一份进度记录，因此定时运行、设置页运行和顶栏运行都会显示在这里。

一次同步在宿主中运行，使用自己的 600 秒预算，不因发起它的页面请求结束而中止。关闭或刷新页面只会结束那次调用，同步继续完成，重新打开后从顶栏指示读取结果。同步中途失败时，之前已完成的范围保持已提交，下次运行从游标继续。

一次运行在**运行日志**中留下开始、结束两行，加上有内容变化的范围各一行；活动记录行用工作区名称标示范围，不写 `activity-workspace-` 开头的散列键。没有变化的范围不逐条记录，按记忆范围与活动记录分别汇总成一行，给出数量与合计耗时，例如 `memory: 3 ranges unchanged` 与 `activity: 3 scopes unchanged`。失败仍逐条指明范围并附原因链。

单个请求遇到连接超时、连接被拒绝、连接中断或名称解析失败时最多尝试三次，间隔 400 毫秒与 1.2 秒。同步按范围顺序进行，一次网络抖动不应让已完成的范围之后的其余范围全部放弃，因此传输失败会重试；服务器给出的答案不重试，包括冲突、认证失败、摘要不匹配和分页不连续，因为这些重复请求只会得到同样的结果。

旧版手工填写的工作区同步名称与 DSH 工作区名称相同时，工作区存储模式可续用原服务器范围。共享数据目录使用新的全局范围，首次运行时从保留完整数据的主机同步。

Codex 和 ZCode 的 MCP 进程也可通过同样的两个环境变量接入共享工作准则。旧同步仓库中的历史不会自动搬到服务器；先把所需记忆恢复到本机，再发布本机副本。详见[同步协议](architecture.md#同步服务协议)。

服务不可达时 MCP 仍可工作：读取返回本机的工作准则，写入照常提交到本机，结果中带 `sync` 字段说明本次未同步及原因。恢复连接后下一次读写会自动同步。未设置这两个变量时工具保持原有输出格式，不含 `sync` 字段。

<a id="ops-记忆整理"></a>

#### 记忆整理

整理复用既有的审查账本，唯一的入口是**存储**中**记忆整理**那一行的**整理记忆**：

- **整理要求**说明这次整理要达成什么，例如“保留短句风格，别合并同义项”。它只描述目标，不会放宽权限：一条操作能包含什么仍由 Host 决定。整理完成后页面会说明是否参考了你的要求，以及参考了远端多少条本机没有的记忆。
- 方案以待审查建议的形式出现，不会自动写入。它列出每条操作与理由，可以**接受**后**执行**，也可以拒绝，或先留下意见。
- 已拒绝的方案要先**重新打开**才能再整理：账本里已决定的建议由其决定回答，只有重新打开后，你的意见才会进入下一次 run 读到的证据，所以顺序是「写下意见 → 重新打开 → 再整理」。
- 接受后的方案可以只执行一部分：每条操作前有复选框，只列出还没执行过的位置，**全选**/**全不选**切换整组，按钮会显示本次执行几条；一条都没选时直接提示，而不是什么也不做。账本逐条记录执行过的位置（`appliedOperations`），并显示为「已执行 {count}/{total} 条」，因此只执行了一部分的方案仍留在列表里，直到它的每条操作都执行过为止。
- 全部执行完的方案离开列表，收进**已执行的历史方案**弹窗，只供回看；重新打开它不会撤销已经写入的改动，而是把整份方案恢复成待审查、可以重新决定。
- 只读 Host 依然可以读取和批注账本；需要可写部署的是“执行”。

<a id="ops-恢复演练"></a>

#### 恢复演练

1. 在“存储”中将“数据目录”设为“自定义”，填写一个隔离目录并应用。
2. 确认状态页显示的当前实际读写根正是该目录。
3. 在“备份与迁移”中选择备份，阅读预检摘要后执行导入。
4. 在状态页检查 Runtime、Documents、Memory Spaces 与目录。
5. 用一个聚焦查询验证直接检索，再阅读一份档案。
6. 验证无误后再决定是否切换正式范围。

不要在没有备份时把恢复直接指向唯一生产根。

<a id="ops-文件系统级快照"></a>

#### 文件系统级快照

需要保留预留 `state` 或做离线完整快照时，可以停止所有使用该根的 DSH / Mnemon 进程后复制：

```text
<storageRoot>/runtime
<storageRoot>/documents
<storageRoot>/data
<storageRoot>/state    # 若存在；不在内置 ZIP 的四类数据组件中
```

复制完成后生成文件清单或校验和，并在隔离路径演练恢复。不要在多个进程仍写入时把普通目录复制当作一致快照。

<a id="ops-切换存储范围"></a>

### 切换存储范围

宿主支持时，可用**选择目录**打开 DSH 原生选择器。选择只填入自定义路径草稿；**应用**沿用手动输入的保存路径，**放弃修改**恢复草稿。选择器报错后仍可手动输入。

保存 `global` / `workspace` / `custom` / `workspaces` 后，Host 先初始化新运行图，再原子切换；页面自动重新读取，但**不会迁移数据**：

```text
旧范围 -- 保存设置 --> 新的空目录或既有目录

不自动复制
不自动合并
不自动删除
```

推荐迁移流程：在旧范围导出 ZIP → 切换到新范围并确认显示目录 → 导入 ZIP → 验证。工作区模式下先确认查看工作区与会话执行工作区是否是预期目标。

使用 `workspaces` 时，备份整个集中目录可覆盖所有工作区，导出 Pack 则只覆盖所选工作区。移动或重命名工作区会产生新路径哈希；恢复旧数据需要操作者显式执行。

现有回合和已委托的子 Agent activation 可能仍使用旧运行图。迁移或停用其数据前，应等待它们结束或取消这些任务。父回合结束本身不会释放异步子任务的委托；新创建或冷恢复的 activation 会捕获自己获准使用的 generation。

<a id="ops-停用完整-starter"></a>

### 停用完整 Starter

既有的 `mnemon` Entry 继续作为整个 Starter 的生命周期总开关。需要停用 Mnemon 时，在 profile patch 中加入以下配置并重启 DSH；不需要逐项停用 Source 或 Strategy：

```yaml
- id: mnemon
  disabled: true
```

该开关会同时停用 Core/Host、三个随附 Source 与随附的 Strategy 增强，不会卸载包或删除记忆数据。删除该覆盖项，或把它改为 `false`，再重启 DSH，即可重新启用完整 Starter。

<a id="ops-cloud-hosted-webui"></a>

<a id="ops-云端-webui"></a>

### 云端 WebUI

[兼容性矩阵](usage.md)列出的 DSH 版本是支持的 registry 安装目标。页面、每个 RPC 与每条 stream 都通过 Host 输出的启动 token URL 建立同一份、与 authority 绑定的浏览器会话。`--trusted-host` 仍只是 Host/Origin 防线，不能替代 HTTPS 或部署层访问控制。

1. 在反向代理或访问网关终止 HTTPS，并只向预期用户开放公网入口。把同源的 `/` 与 `/api` 流量（包括 stream）代理到 `http://127.0.0.1:3080`，同时保留外部 `Host` authority。
2. 使用外部 authority 启动回环服务。参数应为裸 `host[:port]`，不是 URL：

   ```sh
   dsh web --trusted-host memory.example.com --no-open
   ```

   公网入口使用非默认端口时，应传入准确 authority，例如 `memory.example.com:8443`。DSH 会刻意拒绝 `--host 0.0.0.0`；请让服务保持在回环地址，只由代理或 SSH tunnel 访问。
3. 如果浏览器还没有该公网 authority 的有效 Cookie，请使用终端里以 `dsh web: ...` 输出的启动 token URL。经过反向代理时，只把其中的回环 origin 替换成公网 HTTPS origin，保留 `/` 路径与 `?token=...` query。例如把 `http://127.0.0.1:3080/?token=...` 转为 `https://memory.example.com/?token=...`。该 URL 等同凭据，不要放入日志、Issue 或聊天。DSH 会把它交换为 HttpOnly、SameSite Cookie，再重定向到干净的 `/`；尚未过期且 authority 相同的 Cookie 可以跨 Host 重启继续使用。
4. 打开干净的公网 URL，确认“状态”和**设置**页都能加载，并且整页刷新后仍保持认证。远程设置默认只读；需要管理时，先应用[显式远程管理授权](dsh-operations.md#ops-remote-management)、重启 DSH，再验证一次有意的小范围保存。

HTTP 403 可能来自 Host/Origin 不匹配，或旧远程 Client 仍调用独立通道。请检查 `--trusted-host`、公网 authority 与代理路由，再升级 dsh-mnemo-weave、重启 DSH 并刷新浏览器；远程 Mnemon 调用使用已认证 API Gateway。HTTP 401 需要恢复 Host 浏览器认证或配对。若返回远程管理需要 `remoteAccess: trusted-host`，则是另一个 Mnemon 授权检查；浏览器认证成功本身不授予管理权限。

<a id="ops-remote-management"></a>

<a id="ops-远程管理"></a>

#### 远程管理

对于已认证的远程客户端，`remoteAccess: trusted-host` 授予管理操作；远程读取与小范围激活不需要该授权。没有该授权时，远程页面的记忆系统与插件设置会写明只读的原因。本机浏览器与 DSH 桌面版窗口不是远程客户端，不需要该授权。仅为预期的已认证用户配置远程管理权限。

1. 打开 `~/.dsh/profiles/web/cordis.patch.yml`；如果设置了 `DSH_HOME`，则路径为 `$DSH_HOME/profiles/web/cordis.patch.yml`。如果已经有顶层 `- id: mnemon`，请直接修改该项，不要添加重复项。如果初始化文件仍以 `[]` 结尾，请用下面的完整配置行替换它；否则把该行追加到现有顶层 YAML 列表：

   ```yaml
   - id: mnemon
     config:
       routingGuidance: true
       lifecycleEnabled: true
       recallMode: guided
       writebackMode: guided
       idleReviewMs: 30000
       tabEnabled: true
       writeEnabled: true
       remoteAccess: trusted-host
       timeoutMs: 10000
       defaultRecallLimit: 10
       embedding:
         enabled: false
         endpoint: http://localhost:11434
         model: nomic-embed-text
       recallQuality:
         policy: strict-v1
         lowScoreThreshold: 0.25
         highScoreThreshold: 0.6
         candidateMultiplier: 3
         maxMediumResults: 4
         maxRankedResults: 4
         maxUnknownResults: 2
   ```

   Profile patch 会替换目标行的完整 `config`，不会只深度合并一个字段。请保留已有自定义项；插件升级后用 `dsh web --dump-default-config` 对照它，避免遮蔽新增的包内默认值。
2. 运行 `dsh web --dump-config` 检查最终配置树。确认最后的 `mnemon` 行包含 `remoteAccess: trusted-host`，并且 stderr 没有报告无法匹配 `mnemon` 目标。
3. 使用同一条 `--trusted-host` 命令启动 DSH。每次修改 `remoteAccess` 后都要重启，因为 Mnemon 只在启动时捕获该策略。最后通过已认证远程连接验证“状态”、设置加载和一次有意的小范围保存。

<a id="ops-embedding-credentials"></a>

<a id="ops-向量嵌入凭据"></a>

### 向量嵌入凭据

在**设置 → 记忆空间 → Mnemon Native**中，新 API Key 保存为 DSH 凭据库中与 Endpoint 绑定的记录，Profile 仅保留不透明的 `embedding.apiKeyRef`。这个页面不会收到已保存的密钥。凭据库及其磁盘保护由 DSH 负责；这里承诺的是与主设置文件分离，不表示额外加密或使用系统钥匙串。

升级后，已有的明文 `embedding.apiKey` 配置继续可用。点击**将已有明文密钥迁入 DSH 凭据库**，或保存嵌入连接，即可迁移。Host 先写入并读回校验新记录，再替换 Profile 中的值；保存失败保留原连接。密钥输入留空会保留当前密钥。修改 Endpoint 时，需要新密钥、明确配置环境变量，或移除旧引用。**移除本连接的密钥和环境变量引用**是显式操作，可通过恢复配置撤销；它不会删除凭据库记录，因此其他引用和回滚配置仍可使用这些记录。

也可配置 `embedding.apiKeyEnv: MY_EMBEDDING_API_KEY`，并给 DSH 进程提供该环境变量。每次调用 CLI 时读取它，优先于凭据引用和旧明文密钥。变量缺失、为空或凭据不可读时，会明确报错，不会发出空密钥请求，也不会静默改用其他凭据。`embedding.enabled: false` 时，仍原样继承 Mnemon CLI 的环境变量。没有凭据服务的 Host 可使用环境变量方案。

请一起升级 Starter 与 Memory Spaces Source。新 Source UI 搭配旧 Starter 时，现有连接仍可用，但页面不接受新的密钥。旧版插件不能解析 `apiKeyRef`；回滚前请准备已有的 CLI 环境变量方案（`embedding.enabled: false`，设置 `MNEMON_EMBED_ENDPOINT`、`MNEMON_EMBED_MODEL`、`MNEMON_EMBED_API_KEY`，按需设置 `MNEMON_EMBED_PROTOCOL`），或恢复适用的升级前配置。迁移可写 Profile 覆盖值不能删除继承/只读基础文件及历史备份里的旧密钥；确认迁移后连接正常，再自行清除这些原始副本。不要分享凭据文件或带密钥的备份。

<a id="ops-安全边界"></a>

### 安全边界

<a id="ops-进程"></a>
<a id="ops-文件"></a>
<a id="ops-web-与模型"></a>

Host 调用 Mnemon CLI 时不经过 shell，限制每次调用的时间与输出，并通过锁与修订让写入串行。浏览器既拿不到凭据，也不能启动进程；每个任务 Agent 只拿到其任务需要的记忆工具。各项边界的细节见[架构设计](architecture.md#design-安全边界)。

这些边界不是秘密扫描器。当前没有确定性的凭据检测；不要提交密钥、token、私钥和原始敏感日志。

从技能管理市场安装的技能是 Agent 会照着执行的指令，也可能带有脚本。dsh-mnemo-weave 自身从不运行技能里的脚本：每次安装前都可预览，网站发布的压缩包必须与其公布的摘要一致，压缩包不得包含链接或技能文件夹之外的路径，大小与文件数也有上限。安装前请先审阅技能，见[技能管理指南](dsh-operations.md#skills-数据与信任)。

#### 安全问题报告

按 [SECURITY.md](../SECURITY.md) 私下报告漏洞，不要创建公开 issue。数据丢失、路径穿越、锁 / revision 绕过、子 Agent 隔离破坏和 WebUI 记忆内容注入都在范围内。

<a id="ops-故障排查"></a>

### 故障排查

`mnemon.cliPath` 接受显式路径，也接受按 Host 的 PATH 查找的命令名。DSH 运行时，若二进制安装或恢复到既有搜索目录，点击记忆系统顶栏的**刷新**即可更新可用状态，无需重启；Host 进程环境变量的变化仍需重启。状态与版本检查解析同一个配置命令。

| 现象 | 检查与处理 |
|---|---|
| Windows 切换会话时终端窗口闪现 | 更新 Starter，或独立安装的 Runtime Source，然后重启 DSH Host。Runtime 的 Git 分支检测会隐藏控制台窗口；Git 失败、超时或 HEAD 分离时仍回退到不按分支筛选的 Runtime 视图。 |
| 写入含补充 Unicode 字符的长 Runtime 记忆后，同一会话每次请求都返回 HTTP 400 | 检查历史 `tool/result.data.meta.item.title` 或 `excerpt` 中是否有不成对的代理字符（[#548](https://github.com/omdsh-dev/dsh-mnemon/issues/548)）。修复会在原有活动摘要长度限制内保留完整码点，存储的记忆正文不变。更新到包含修复的构建并重启 DSH。已有会话记录不会被改写：可在新会话中继续使用同一份记忆，并保留受影响的会话供单独恢复。仅凭通用 400 错误不能确认此原因。 |
| Mnemon 不可用 | macOS/Linux 运行 `command -v mnemon`、`mnemon --version`；Windows PowerShell 运行 `Get-Command mnemon`、`Test-Path "$env:LOCALAPPDATA\Programs\mnemon\mnemon.exe"`。设置 `MNEMON_CLI_PATH` 或 `mnemon.cliPath` 后重启 |
| Electron 桌面 Host 无法运行 npm CLI 脚本 | 经过验证的 npm 启动器仅在子进程中设置 `ELECTRON_RUN_AS_NODE=1`。如果桌面壳关闭了 [Electron `runAsNode` fuse](https://www.electronjs.org/docs/latest/tutorial/fuses#runasnode)，该变量会被忽略；请将 `mnemon.cliPath` 指向官方原生二进制（Windows 为 `mnemon.exe`）。npm 自动更新仍需要 Host 能够运行 JavaScript 启动器 |
| Headless Agent 没有 Mnemon 工具 | 插件按 profile 独立安装；按[本地链接步骤](usage.md#deepseek-harness)安装，使用 `headless` profile，Web profile 的安装不会自动带入 |
| 会话中的记忆标签底部被输入框遮挡 | 记忆标签默认收起输入框，点击**展开输入框** / **收起输入框**可保存当前浏览器偏好；草稿与附件保留在 DSH 编辑器中。切回对话恢复输入框，待处理交互优先显示，技能的**使用**会展开输入框。多个会话分栏或 Host 不提供输入框插槽时保留正常输入框，记忆页面按实际高度留出滚动空间。 |
| 找不到“记忆系统”入口 | 检查 `tabEnabled=true`；`displayMode=sidebar` 使用侧边栏，`displayMode=builtin` 使用已打开会话的标签页。本地 link 先 `pnpm run build` 再重启 profile |
| 旧的 `buildin` 偏好打开了会话标签页 | 它会保存为 `builtin`；如需独立入口，请在**界面**中选择**侧边栏**。记忆范围与已存数据不变 |
| 状态正常但召回为空 | 检查 active 记忆空间、存储范围、查看目录、会话实际目录和查询是否足够聚焦 |
| 顶部提示目录未对齐 | 工作台正在查看另一个工作区；确认是否为预期范围。工作台任务在查看工作区执行，对话工具仍使用所属会话范围 |
| 设置看起来没有变化 | 开关与选择器立即生效，需要输入的值要点击**应用**；写入失败时控件旁会显示原因并恢复为已保存的值 |
| 自定义目录被拒绝 | 使用绝对路径、`~` 或 `~/...` |
| `memoryBodyId is required...` | active 数量不是恰好 1；显式选择目标 |
| `memory space is not active for reading` | 在概览激活目标；写入 inactive 可以，读取不行 |
| Provider 错误 | 审查需要受 guard 保护的本地子 Agent；默认有界 `spawn`，可选择 `fork`。安装了 Team 工具时如需继续审查，可选择 `idleReview.agentTeams: scoped`，默认仍为 `pause`；重试前核对部分写入回执 |
| 本地模型（例如 Ollama 上的 Qwen3.x）下空闲审查报 `no user query found in messages` | 工具结果填满模型的上下文窗口后，Ollama 截断时丢掉了子代理的任务提示。0.5.22 起，Mnemon 会给被拒的子代理步骤追加一条用户消息并重试（[#327](https://github.com/omdsh-dev/dsh-mnemon/issues/327)），请更新 dsh-mnemo-weave。调大 Ollama 的上下文长度（`OLLAMA_CONTEXT_LENGTH` 或模型的 `num_ctx`）也能避免截断。审查可能在失败前已创建工作区档案，请核对部分写入回执 |
| 侧栏“未分组”下出现空的“未命名”会话，每运行一次记忆任务就多一些 | 上游 0.5.32 及更早版本没有给记忆任务（存入记忆、Agent 查询、档案归档、运行时记忆容量维护、记忆整理等）的任务 Agent 加上子代理来源标记，DSH 只要没有该会话的投影缓存记录，就把它当作对话列出（[#435](https://github.com/omdsh-dev/dsh-mnemon/issues/435)）。当前版本的任务记录显示方式取决于 DSH 客户端。已有的这些行会保留：dsh-mnemo-weave 不会删除它们，记忆数据不受影响。想隐藏某一行，在该行上使用“归档会话”；DSH 会把它保留在已归档筛选中，“取消归档”即可恢复 |
| Runtime replace 超容量 | 缩短 replacement 或先显式整理；自动维护只处理 add 溢出 |
| Document source path 被拒绝 | 路径必须在会话工作区内，且不能引用受管 Documents 目录 |
| CLI timeout | 增大 `timeoutMs`；大 Store 的状态与图谱可能超过 10 秒 |
| lock timeout | 检查其他写进程，不要删除仍属于活跃进程的 lock |
| ZIP 导出提示 WAL busy | 等待 Memory Space 写入完成并重试；不要绕过未 checkpoint WAL 检查 |
| ZIP 导入 checksum / schema 失败 | 备份损坏或格式不兼容；保留当前根，不要手工解压覆盖 |
| 更新按钮不出现 | 当前已是最新、远程检查失败，或安装来源是 link / 手工模式；按面板提示沿原方式更新 |
| 已认证远程页面能读取或激活记忆空间，但不能保存设置或执行其他写入 | 默认管理限制；确需远程管理时，保留当前配置、在本地设置 `remoteAccess: trusted-host` 并重启 DSH |
| DSH 桌面版记忆页面只读 | 核对当前窗口是否连接本机宿主，以及插件的 `writeEnabled` 设置。远程窗口还需满足对应的写入授权。 |
| Profile 中装有 dshmarket，DSH 启动时提示 `mkt-client-dsh-mnemo-weave-source-memory-spaces` 未能激活（`Memory Spaces requires at least one explicit Provider child`），状态页的运行时记忆或工作区档案出现两次，或每轮对话都因 `found ambiguous working-context Sources` 失败 | Profile 中另外单独安装了某个 Source 包，dshmarket 1.66 又把它作为仅客户端挂载加载了一次（[#359](https://github.com/omdsh-dev/dsh-mnemon/issues/359)）。核对 profile 是否同时加载了重复来源，调整后重启 DSH。把单独安装的 Source 从 Profile 中移除也能消除这些问题，例如 `dsh plugin --profile web remove dsh-mnemo-weave-source-memory-spaces`，因为 Starter 自带这些组件。记忆数据不受影响 |
| 技能管理的**进化**一直是空的、回合下显示**复盘失败**，或市场提示 GitHub 拒绝列出仓库 | 自进化默认关闭；一次复盘需要几轮实际工作和一次停顿。GitHub 对未认证请求每小时限 60 次：在 DSH 的运行环境中设置 `GITHUB_TOKEN` 或 `GH_TOKEN` 后重启。见[技能管理常见问题](dsh-operations.md#skills-常见问题) |
| DSH 重启或 authority 改变后 Mnemon RPC 返回 401 | 打开 `dsh web` 输出的启动 URL，让一次性 token 建立新的、与 authority 绑定的浏览器 Cookie |

### 已知限制

<a id="ops-功能只读不等于磁盘只读"></a>

#### 功能只读不等于磁盘只读

`writeEnabled=false` 禁用语义 mutation 与 Pack 导入，但启动可能初始化 / 修复 Runtime 投影，Document 搜索更新 `lastAccessedAt`，Mnemon 读命令也可能迁移数据库。

<a id="ops-documents-的共享范围"></a>

#### Documents 的共享范围

`global` 与 `custom` 可能让多个工作区共享同一 Document index；记录没有独立 workspace ownership 字段。`sourcePaths` 只在写入时相对发起会话 cwd 校验。

<a id="ops-跨系统事务"></a>

#### 跨系统事务

“先冷索引、后移动”保护 active 原文，但不是跨 Mnemon SQLite 与文件系统的可回滚分布式事务。索引后发生 revision 冲突时可能保留重复引用；系统选择保留数据。

<a id="ops-后台审查配额"></a>

#### 后台审查配额

活动评分、最近 checkpoint 与重试状态未持久化；Host 重启会清空未处理活动。失败退避、熔断和人工重试入口尚未实现。

<a id="ops-版本与国际化"></a>

#### 版本与国际化

支持的 DSH 版本见[兼容性矩阵](usage.md)。Web 界面为中英文双语，但命令、工具卡、兼容元数据和部分错误仍未完全国际化。

<a id="providers-长期记忆-provider"></a>

## 长期记忆 Provider

记忆空间保存 dsh-mnemo-weave 的长期记忆。本项目只支持一种 Provider：**Mnemon Native**，即官方 CLI 操作本地 `mnemon.db`。它是唯一的长期记忆后端，没有第三方适配器，也不内置外部后端服务。

Mnemon Native 需要 Mnemon CLI。缺少 CLI 时记忆空间没有可用的 Provider，创建空间会失败并提示先安装 CLI。

![插件中的记忆空间页面](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/plugin-spaces.jpg)

<a id="providers-provider-能力矩阵"></a>

### Provider 能力矩阵

| Provider | 数据面 | 召回 / 浏览 | 图谱 / 关联 | 写入 | 遗忘 |
|---|---|---|---|---|---|
| **Mnemon Native** | 官方 CLI 操作本地 `mnemon.db` | 支持 / 支持 | 完整类型图谱 / 支持 | 精确写入 | 软删除 |

Host 只暴露适配器能够兑现的能力；UI 与 Agent 工具不会伪造缺失的图谱、关联、链接、浏览或删除语义。

<a id="providers-windows-cli-安装"></a>

### Windows CLI 安装

Mnemon 可以通过 npm 或 pnpm 全局安装（`pnpm add -g @mnemon-dev/mnemon@latest`）。自定义全局目录未暴露给 DSH 时，请在 Provider 的 `cliPath` 中填写可执行文件的绝对路径，显式路径仍优先。环境检查及 pnpm 更新方式见 [CLI 安装与发现](usage.md#install-mnemon-cli-的其他安装方式)。

<a id="providers-服务与记忆空间字段"></a>

### 服务与记忆空间字段

| Provider | 工作区行为 | 记忆空间页面中的服务配置 | 记忆空间中的实例配置 |
|---|---|---|---|
| Mnemon Native | 自动随工作区切换 | 无，由 CLI 配置管理 | Store 身份、嵌入设置 |

“记忆空间”页面（**设置 → 记忆空间**）保存 Mnemon Native 的服务配置与嵌入设置。“**记忆空间 → 概览**”负责创建、编辑、启停与删除记忆空间。Host 在调用适配器前合并两层配置。

启动时会在每个 Host 进程中对每个数据目录发现一次本机已有的 Mnemon Store，把它们同步进记忆空间目录；只读部署或记忆空间层关闭时不运行。

<a id="providers-召回评分语义"></a>

### 召回评分语义

Mnemon Native 的 `smart` 召回请求详细信号，先将 Source 的候选请求扩大为 `min(50, max(20, requested * 4))`，再应用返回数量限制。有正向向量相似度时，将相似度限制在 0–1、优先排序，并用于召回质量阈值。没有相似度的结果保持无分数，但已被替代的事实保留 CLI 的降权，且不会高于其原有分数。全部相似度缺失或非正时，保留 CLI 原有顺序和分数。`keyword` 与 `basic` 保留原有命令和分数。旧 CLI 拒绝 `--verbose` 时只去掉该参数重试一次，因为这些版本的默认响应已包含信号。这是在 CLI 候选内做有界重排，不是全库向量搜索，也不代表校准概率。普通召回会记录较大候选池的访问；检查仍使用 `--readonly`。

参见[召回质量策略](dsh-configuration.md#召回质量策略)。

<a id="providers-运维边界"></a>

### 运维边界

- WebUI 不直接调用本地 CLI；Provider I/O 都留在 Host，统一具备取消、超时、进程输出上限和 shell-disabled 参数执行。
- “断开”记忆空间只删除本地目录登记，不删除底层数据。单条记忆的“遗忘”是另一项按能力开放的操作。
- Mnemon Native 会记录使用。Agent、`/mnemon recall` 或 **Agent 查询**发起的召回，会把查询写入存储的操作日志（`mnemon log`，保留最近 5,000 条操作），并把返回的记忆计为已访问；Mnemon 的保留策略会参考访问次数（`mnemon gc` 不会建议清理访问过三次的记忆）。记忆系统自身的检索（记忆空间页上的**直接检索**和实体页上的**查找相关记忆**）改为用 `mnemon --readonly` 读取快照，与它的列表和图谱一样，不做任何改动。Host 归档时核验自身写入的检查读取实时存储，因为其他进程写入期间，快照不一定与存储一致。
- Mnemon Pack 包含 Mnemon Native 记忆空间、运行时与档案。


## 技能管理

[文档首页](../README.md)

**技能管理**把一个工作区能加载的 DSH 技能集中在一处：开关技能、在对话里使用、编辑、回到旧版本。它还能从你的真实对话中改进技能，每次改动先经过测试再由你采纳，并从技能已经发布的各个地方安装更多技能。技能管理目前是**实验性**组件：随 dsh-mnemo-weave 安装并默认开启，自进化则要等你手动开启。

| 位置 | 能做什么 | 怎么打开 |
|---|---|---|
| [技能管理页面](dsh-operations.md#skills-技能管理页面) | 管理技能、处理自进化的建议、测试技能、安装更多技能 | **记忆系统 → 技能管理**，或它自己的侧边栏入口 |
| [对话中](dsh-operations.md#skills-对话中) | 看一个回合用了哪些技能、复盘提出了什么建议 | 回合结束后下方的**本回合技能**一行 |
| [设置](dsh-operations.md#skills-设置) | 开关自进化及其参数、对话提示和侧边栏入口 | **设置 → 技能管理**，或技能管理页面上的齿轮 |

技能是一个带 `SKILL.md` 的文件夹，采用 DSH 读取的 [Agent Skills](https://agentskills.io/specification) 格式。页面本身从不调用模型；技能只通过 DSH 自带的 `skill` 工具进入模型，技能管理不会往回合的记忆 View 里加任何内容。

下面的截图来自 [v0.5.34 技能管理图集](https://github.com/omdsh-dev/dsh-mnemon/blob/main/docs/assets/skills-v0.5.34/README.md)，项目是虚构的 Lumen：助手用 `release-notes` 技能写版本说明，用户纠正了格式，之后的事交给自进化。这些截图记录的是当时的界面：技能管理所在的一行当时显示在插件的**记忆系统**页面上，现在它在记忆系统的**设置**页中。

通过链接引入的技能根目录、技能包目录及 `SKILL.md` 仍可查看和使用，默认只读。如需优化可信的共享技能，可在**设置 → 技能管理**的**技能**标签中开启**允许更新链接技能**（`skills.allowLinkedUpdates`，默认 `false`）。此后编辑、调用开关、版本恢复和草案采纳会更新解析后的原始文件，保留链接本身，影响所有共享它的 Agent。内容哈希与管理修订检查仍会拒绝过期写入；自进化和自动采纳仍需各自的开关。关闭后再次禁止后续链接更新和采纳，已有修改与版本历史保留。在链接根目录中创建或安装新技能、回收站与移除规则均不改变，普通本地技能流程不变。独立技能 Source 实例可设置自身的 `allowLinkedUpdates`。

<a id="skills-技能管理页面"></a>

### 技能管理页面

页面有五个标签：**技能**、**进化**、**评测**、**市场**和**回收站**。**进化**上的数字表示有多少建议和草案在等你处理。

<a id="skills-技能"></a>

#### 技能

宽屏下，技能列表和选中技能的文档分别滚动。切换技能时，详情从顶部打开，列表保留原来的位置。窄屏下，可滚动的列表仍放在文档上方。

![技能：按所在位置分组的技能，其中一个被覆盖；release-notes 有一条改进待处理](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/skills-v0.5.34/zh-CN/skills-library.jpg)

列表按 DSH 的优先顺序，把能加载的每个 `SKILL.md` 按所在位置分组：项目的 `.dsh/skills`、`.agents/skills`，然后是你的 `~/.dsh/skills`、`~/.agents/skills`。同名技能只加载最靠前的一个，其余标为**被覆盖**。DSH 会拒绝加载的文件在列表下方计数（*N 个文件无法加载*），展开可见原因。

- 每行有一个**开关**，同时控制模型能否加载、`/` 菜单里是否出现；悬停时出现**使用**，点击回到对话并在输入框里填入 `/技能名`。行上的小圆点表示 DSH 实际加载的那份技能有改进在等待。
- **新建**按名称和描述在你选的位置写一个 `SKILL.md`；名称只能是小写字母、数字和单个连字符。
- 详情渲染 `SKILL.md`，提供**使用**、**编辑**和一个菜单：**生成改进草案**（由任务 Agent 写草案，可附上你的要求）与**移除**（技能文件夹移入**回收站**标签页）。
- **调用**是一个选项：**自动与 / 命令**、**仅 / 命令**、**仅自动加载**或**关闭**，写入的是 DSH 自己的 `disable-model-invocation` 和 `user-invocable` 键。
- **测试**是一行，显示用例数和上次得分，点击进入**评测**里的这个技能。**版本**和**文件**默认折叠：每次改动（新建、编辑、调用方式、安装、采纳的改进、恢复）都会留下一个版本，可以对比和恢复。

每次写入都以文件哈希为准：如果技能在此期间被别处改过，不会被覆盖。

<a id="skills-回收站"></a>

#### 回收站

**回收站**列出移除技能的名称、移除时间、原位置、技能目录或单个文件的布局以及大小。**恢复**把已知来源的条目放回记录的原路径；即使切换到其他工作区，项目技能仍恢复到原项目。旧条目没有可确定的来源时，需要先选择恢复位置。

同名技能已存在时，可以改名恢复、明确确认替换，或取消。替换会校验当前文件的哈希，并把被替换的技能保留在回收站。改名会更新技能名称并保留目录中的其他文件。操作后列表和数量会立即刷新。

**彻底删除**需要输入技能名确认，**清空回收站**也有单独的确认。这两种操作会永久删除文件；普通的**移除**会保留可恢复的文件。

<a id="skills-进化"></a>

#### 进化

页面会跟踪进行中的草案和评测，在任务结束后再刷新一次卡片；回到窗口或浏览器标签页时也会重新读取状态。

宽屏下，待处理和已处理列表与右侧详情分别滚动。切换条目时，详情从顶部显示，列表保留当前浏览位置。窄屏仍将列表放在详情上方。

**全局模型**选择生成和重写草案的模型；**所选草案模型**只覆盖当前建议。清空单项选择后跟随全局，两者均清空时跟随任务 Agent。生成草案后自动启动的回测使用该草案所选的模型。选择保存在 `skills/preferences.json`，重启后仍有效；旧版本会忽略这个可选文件。

**待处理**列出等你处理的内容：建议，以及直接为某个技能生成的草案。**已处理**保留已采纳、已忽略、已过期或已失效的建议。**证据**列出复盘读过的对话。星形按钮**复盘本会话**立即复盘当前对话，不必等它停下来。

删除建议后，复盘记录和证据中的相关入口也会移除，已记录的对话和评测用例仍然保留。旧记录中指向已删除建议的入口会在读取时自动过滤。如果建议在页面打开期间被删除，详情会显示已删除提示；其他加载错误可以重试。

| 建议及其证据 | 回测过的草案 |
|---|---|
| ![进化 · 待处理：改进 release-notes 的建议，展开了所依据的证据](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/skills-v0.5.34/zh-CN/skills-suggestion.jpg) | ![建议下的草案：说明与改动、回测“当前 40 → 草案 93 +53”，以及差异](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/skills-v0.5.34/zh-CN/skills-draft.jpg) |

- **建议**用一句话说明它要做什么（新建技能或改进某个技能），并附上理由、来自哪段对话和置信度。**生成草案**让任务 Agent 写出新的 `SKILL.md`；**忽略**则放到一边。展开**证据**能看到它引用的对话步骤，每一段都能跳到完整记录。
- **草案**展示说明与改动、一行回测结果（例如*当前 40 → 草案 93 +53*，点开是每个用例的判定）以及差异。**采纳**写入（新技能可选写到用户技能或项目技能），**放弃**丢弃，菜单里还有**编辑草案**和**按要求重写**。得分低于当前版本的草案，采纳前会再确认一次。
- **证据**把每段对话展示成编号步骤（你的消息、工具调用及其失败、技能加载），以及复盘在其上的标注。**置顶**可防止记录被清理；勾选若干步骤后点**生成**，可为某个技能生成测试用例。

![进化 · 证据：四段记录的对话；版本说明这段对话的信号与编号步骤](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/skills-v0.5.34/zh-CN/skills-evidence.jpg)

改进建议会保留原技能文件及其所属项目，切换存储范围不会改变目标。建议中的**当前技能文件**展示该文件；草案差异、按要求重写、基线回测和采纳都使用同一来源。其他项目或其他根目录中的同名技能分别处理。

旧项目建议可从所引用的复盘轨迹恢复唯一的原工作区，关联草案也可沿用。来源缺失或冲突时，请切换到原工作区，在**技能**页打开该技能，通过**改进**重新生成草案；如有需要，先从**编辑草案**复制有用改动。现有草案和证据会保留。文件被删除、移动或无法读取时会单独提示，不会误采纳到其他同名技能。

<a id="skills-可选的自动采纳"></a>

#### 可选的自动采纳

**自动采纳新建议**（`skills.autoAdopt`）默认关闭。开启自进化、草案自动回测和此开关后，仅处理空闲审查**新建**的建议，并继续分别遵守**新建技能**与**改进已有技能**开关。开启时不会批量处理历史建议、手动复盘建议，或只被再次补强的已有建议。

每个建议先起草，再以相同的回测模型、思考强度和完整启用用例集，新跑一组基线与候选回测。起草沿用建议覆盖／全局草案模型；评测沿用技能覆盖／全局回测模型，未选择时使用任务 Agent 默认模型。所有检查项必须有明确判定；错误、中断、不完整、图片依赖、用例或草案变动、无法确定模型时，保留人工审查并显示原因。启用用例数超过**每次回测用例数**时，也会停止自动处理，避免擅自提高模型工作上限或默默漏测；可调整启用用例或上限供后续新建议使用，本次建议仍由人工处理。

候选须每个用例都不退步，且不丢失任何原先通过的检查项。退步时，将基线／草案分数和逐项结果带入重写指导，最多**重写两次**（共三个草案）。仍退步则留在 review。建议的**自动采纳活动记录**显示阶段、原因和双方分数。最终仍由 Source 在原有写锁内重新核对草案、用例、完整结果与当前技能 hash，再沿用原有采纳、版本记录和环境校验。

关闭自动采纳、自动回测、自进化或对应的新建／改进权限后，相关任务在下一检查点停止；等待 Source 写锁的采纳也会检查取消。内存队列最多 16 个建议，串行处理，回测继续遵守已有并发与超时限制。重启不自动续跑；下述候选额度跨重启保留。回测仍是文本模拟，不代表真实浏览器、登录、安装等外部操作已经验证。

<a id="skills-每日候选预算与复用价值参考"></a>

#### 每日候选预算与复用价值参考

**每日自动处理候选数**（`skills.autoAdoptDailyLimit`，默认 `2`，范围 `0..100`）限制同一 Skills 存储目录中的新自动候选。**每日额度时区**（`skills.autoAdoptTimeZone`）接受 `Asia/Shanghai` 等 IANA 名称；`local` 使用 Host 时区。Source 在写锁内、自动模型工作开始前预留名额，同一技能文件每天最多进入一次。尝试、取消和失败仍计数，最多两次重写共用一个名额。设置为零暂停自动处理，不影响手动起草、回测或采纳。

额度用完后建议保持 pending，**自动采纳活动记录**显示原因、日期、时区和计数；第二天也不会批量处理旧建议。`skills/auto-adoption-budget.json` 独立账本跨重启保留，删除建议或历史不返还额度；切换时区时按记录时间重新计算。保留 72 小时，覆盖 IANA 时区变化下的自然日。升级时纳入仍保留的近期自动活动与复盘记录；升级前已删除的记录无法重建。预算不可读时停止自动处理，仍可人工操作。旧 Source 缺少预留操作时需升级后再自动处理；新 Source 服务旧 Host 时，在最终写入前执行默认额度。已采纳技能保持不变。

建议采用确定性证据规则：至少 3 段不同的引用证据、20 个不同的引用步骤且置信度不低于 0.8，标为**可复用流程**；只有 1 段且不足 20 步，标为**一次性候选**；其余或证据缺失时为**需要判断**，继续显示。一段证据是一次复盘窗口，不一定对应独立会话，页面同时展示两类计数。仅统计已通过落账校验的引用，重复引用不重复计数，模型的 `signals` 不决定分类。中间状态不额外调用模型。

可复用建议优先展示，一次性 pending 候选折叠并提供展开入口；链接能直接打开目标，已在审阅中的草案保持可见。新建或补强建议时记录分类，旧记录读取时派生。分类只调整展示，不删除数据，也不授予自动采纳权限；自动采纳仍需主动开启，并保留已有证据检查与权限边界。

#### 评测

![评测：每个技能的用例数与最近得分；release-notes 的三个用例与逐个用例的回测结果](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/skills-v0.5.34/zh-CN/skills-evals.jpg)

所有技能的测试集中在这里。列表先列有用例的技能（附上次在当前加载版本上的得分），再列没有用例的，最后是建议中提出、尚未创建的技能（**未创建**），后者可直接跳到对应建议。

评测页有独立的**全局模型**，以及按技能保存的**所选回测模型**。手动回测（包括草案与基线的对比）依次使用技能覆盖、评测页全局选择、任务 Agent 默认模型。执行用例和判卷使用同一个所选模型。

- **添加用例**需要标题、用户会怎么说的任务、可选的背景，以及若干检查项，每项标为**必须**或**建议**。用例也会来自复盘和证据。每个用例有开关，展开可见检查项和来源对话。
- **运行回测**用启用的用例测试当前版本；技能尚未创建时，测的是不加载它的表现。回测记录保留最近几次，每次都能展开看逐个用例的判定、模拟执行的步骤和回答。

回测是模拟运行：执行者按技能写出它会怎么做，但不调用工具；评审逐项判定检查项。所有**必须**项都通过，用例才算通过；计分时**必须**项按两倍计算。对比时，任一侧未能运行的用例不计入双方得分。

用例需要截图、扫描件或图表时，在添加或编辑时勾选**依赖图片输入**。纯文本回测无法接收图片：标记的用例显示**未测**，不会调用执行者或裁判，也不计入本次得分和草案与基线的比较。选中的用例全部被标记时，回测完成但没有得分。这是用户明确设置的标记，不会自动识别图片需求，也不提供附件上传。

已有用例仍按纯文本评测，历史记录保持原样；请标记图片依赖用例后重新回测。如果改测转写的文字，可把内容填入**背景**并取消标记。降级到尚未支持此标记的 Host 前，请先关闭这些用例，避免旧 Host 继续模拟它们。

<a id="skills-自进化"></a>

### 自进化

自进化默认关闭，可在[设置](dsh-operations.md#skills-设置)里开启，或在**进化**标签的空白页上直接开启。开启后：

1. 每个回合结束时，Host 记录这一回合的步骤：你的消息、调用的工具及是否失败、加载的技能。令牌、API key 等机密会被替换掉。
2. 自动评估需要同一工作区的两段独立会话。改进已有技能需要两次使用同一技能，并看到同一工具失败后恢复。新建技能需要两次在未加载技能时成功执行同一组具体操作，工具顺序和输入一致。达到积分门槛和空闲等待时间后，任务 Agent 检查这些操作是否构成可复用流程。Host 在运行期间保留跨会话候选。
3. 评估结合两段轨迹、相关准则、工作区档案、正式记忆与技能目录。确认可复用的流程或改进点后提出带证据的建议。也可以手动发起复盘。
4. 只有置信度不低于**最低置信度**的建议才会收下；同一技能文件、同一类建议只保留一条未完成的（新建建议按名称区分）：新证据追加保留，待处理建议在新置信度不低于旧值时可更新摘要与理由，生成草案中或待审阅建议的文案不变；被忽略的建议，一天内不会再由同一段对话提出；每段对话最多保留**单个对话待处理上限**条；建议在**建议有效期**天后过期。改进类建议会记下技能当时的哈希，生成草案前文件被改动就会失效。
5. **生成草案**写出新的 `SKILL.md`。开启**草案自动回测**时，草案和当前版本（新技能则是不加载技能）用同一批用例比较，最多**每次回测用例数**个，结果显示在草案上。
6. 由你采纳、编辑、重写或放弃。默认仍须手动**采纳**；新的空闲审查建议可按上文的可选自动采纳流程处理。

**新建技能建议**与**改进已有技能**可以分别开关，默认均开启。关闭前者只复盘已有技能的改进，关闭后者只提出新技能。Source 按当前技能目录核对类型，因此与已有技能同名的“新建”仍算改进。被关闭的类型及其提出的评测用例不会保存，复盘运行期间关闭开关也会约束这次结果。两项均关闭时暂停自动和手动会话复盘，不再发起模型调用；已有建议仍可手动生成草案、回测和采纳。

复盘失败会记在对应回合下，并保留积分窗口；连续失败三次后，这段对话停止复盘，直到 DSH 重新创建它的 Agent。复盘、草案和回测都以 dsh-mnemo-weave 任务 Agent 运行，使用**任务 Agent 模型**设置选定的模型，见[配置参考](dsh-configuration.md#后台任务-agent-的模型路由)。

裁判给通过项提供执行步骤或模拟答案中的原文引用。宿主核对引用是否存在，缺少有效引用的评分不能用于自动采纳。引用与检查项是否相符仍由裁判判断。

在**草案生成**里，将**草案输出 token 上限**和**重试输出 token 上限**设为模型提供方支持的预算，预算包含推理和完整 `SKILL.md`。两项独立配置，重试不会隐性翻倍你选择的上限。重试上限等于或小于首次值时关闭截断重试。每份草案最多尝试两次，与原有文件校验修正共用重试机会。截断输出会丢弃，只保存完整且校验通过的草案，采纳后才改动已安装技能。失败信息包含实际尝试预算与原文件大小：提供方拒绝预算时应调低；完整文件仍无法容纳时，可缩短技能或选择输出上限更高的模型。准确配置键与范围见[技能管理设置](dsh-configuration.md#技能管理设置)。

`skills.targetScope` 默认保留 `user`，兼容现有安装：升级或修改存储范围不会把新技能写到另一个根目录。需要跟随存储范围时显式选择 `storage`。新建议记录解析后的目标；草案及重新起草保留该目标，采纳沿用草案的目标，除非用户手动选择其他位置。旧版本中没有目标字段的建议在起草时使用当前设置；已有草案保留记录的目标。改进已有技能始终写回 `baseKey` 与记录来源共同确定的原文件（包括所属项目），不受设置、所选存储范围或目标覆盖影响。

项目根来自所选工作区的 Skills Source 目录，遵循 DSH 的发现规则（最近的 `.git` 祖先目录，否则为工作区本身），不使用模型任务的工作目录。缺少工作区/项目或目标不可写时，复盘/起草会显示明确错误，不静默降级到用户技能。采纳时重新检查最终选择的项目：不会重建起草后被删除的项目，用户可以明确改选用户根目录；后续文件系统错误也会显示。不会迁移技能或改变发现优先顺序，默认仍须手动采纳；仅显式启用的自动采纳可以处理新的空闲审查建议。

[配置参考](dsh-configuration.md#技能管理设置)列出了每个键的取值范围和保存位置。

<a id="skills-数据与信任"></a>

### 数据与信任

- **技能就在 DSH 读取的位置。**编辑、安装和采纳都直接写技能文件夹；被删除或替换的技能先移入技能管理的回收区。
- **技能管理自己的数据**放在存储根目录的 `skills/` 文件夹：建议、草案和安装记录，测试用例和回测，记录下来的对话，每个技能的历史版本，以及市场来源和缓存。见[存储模型](architecture.md#storage-技能管理)。这些数据不在 ZIP 备份和 服务器同步之内。
- **记录的对话**只保留复盘需要引用的内容（你的消息，工具名称、参数和失败，技能加载），机密会被替换。最多保留最近 100 段；置顶的、被建议或用例引用的保留得最久。任何一段都可以删除。
- **任务及子代理会话**由 DSH 保存在自己的会话目录（默认 `~/.dsh/sessions/`，实际位置取决于 DSH 配置），与上述 `skills/` 证据记录分开。一次复盘涉及任务 Agent 和委派的执行子代理；释放实例、侧栏隐藏或删除技能证据记录都不会自动清理这些 DSH 会话。Mnemon 当前没有会话清理入口或自动保留期限，它们也不在 Mnemon ZIP 备份或 服务器同步范围内。关闭**自进化**会停止后续自动复盘，不会删除历史记录；手动生成草案、回测等模型操作仍会创建会话。
- **模型调用。**只有自进化、生成草案、回测和从证据生成用例会调用模型，均以任务 Agent 运行；浏览、编辑、开关和安装都不会。
- **市场**会访问 GitHub、skills.sh 和你添加的网站。GitHub 对未认证请求每小时限 60 次；列出一个仓库用一次，并在十分钟内复用。在 DSH 的运行环境里设置 `GITHUB_TOKEN` 或 `GH_TOKEN` 可以提高这个上限。

<a id="skills-常见问题"></a>

### 常见问题

| 现象 | 处理 |
|---|---|
| **进化**一直是空的 | 确认已开启**自进化**及至少一类建议。自动评估需要跨会话的技能问题证据；可以用**复盘本会话**立即评估。 |
| 回合下显示**复盘失败** | 任务 Agent 没能给出结果，积分窗口会保留到下一次。连续失败三次后，这段对话停止复盘，直到 DSH 重新创建它的 Agent。 |
| 提示 *GitHub declined to list …* | GitHub 本小时的额度已用完。稍后再试，或设置 `GITHUB_TOKEN`。skills.sh 的预览仍会用它保存的文本副本展示技能，并注明这一点。 |
| 提示 *skills.sh is busy* 或 *skills.sh 暂时无法搜索* | 稍后再搜，已添加的其他来源不受影响。在**来源**里可以关闭 skills.sh。 |
| 提示 *… publishes no Agent Skills index* | 该网站在所给路径和根目录下都没有 `/.well-known/agent-skills/index.json`。 |
| 草案显示*回测结果无法比较* | 没有任何用例在两侧都运行成功；查看各用例的错误后点**重新回测**。 |


<a id="skills-恢复草案或回测"></a>

#### 恢复草案或回测

草案生成超过 15 分钟、回测超过 45 分钟会停止。最多同时运行两组回测，每组最多并行执行两个用例，运行和等待的任务总数最多 16 个。等待中的任务也可以取消，并计入超时时间。即使模型不响应取消，挂起的任务也会恢复到可重试状态。草案卡片可以取消回测；草案、用例和已有结果会保留。未完成对比时，请先审阅草案再手动采纳。

原技能变更或新建目标出现同名技能时，卡片会说明冲突并提供“重新生成并回测”。重生成读取最新文件并保留原指导；编辑旧草案不会绕过文件哈希校验。生成期间文件再次变更时，记录新草案会被拒绝，旧草案仍保留。Source 启动时及每分钟回收检查会把超时运行记录持久化为中断状态，迟到结果不能重新激活任务。
