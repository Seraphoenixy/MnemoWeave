# DSH 工作台与功能

<a id="start-快速开始"></a>

<a id="start-入门指南"></a>

## 入门指南

本页从装好 dsh-mnemo-weave 之后开始，一直走到对话真正用上记忆。全程使用默认设置：记忆系统位于侧栏、全局存储、分层策略。日常使用不需要了解 View 或 Strategy。

<a id="start-1-命令行安装与升级"></a>

先完成 [DSH 的安装与启用](usage.md#deepseek-harness)，再按以下步骤验证。

<a id="start-2-打开记忆系统"></a>

<a id="start-1-打开记忆系统"></a>

### 1. 打开记忆系统

在侧栏点击**记忆系统**，默认进入**状态**页。

![状态页：每个记忆组件与 Provider](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/memory-status.jpg)

请确认：

- 顶栏显示**已连接**并写明所用的策略；
- 记忆引擎卡片显示 dsh-mnemo-weave 的版本；
- 运行时记忆、工作区档案与记忆空间各有一张没有错误的卡片；
- 存储根目录与你选择的存储范围一致。

即使使用全局存储，工作区档案也需要 DSH 工作区。请为对话选择工作区；“等待工作区”表示缺少项目上下文，而不是缺少 CLI。如果缺少 Mnemon CLI，可在 macOS 或 Linux 上运行 `command -v mnemon` 与 `mnemon --version`，在 Windows 上运行 `Get-Command mnemon`。其他问题见[故障排查](dsh-operations.md#ops-故障排查)。

<a id="start-3-保存第一批记忆"></a>

<a id="start-2-保存第一批记忆"></a>

### 2. 保存第一批记忆

**运行时记忆。** 打开**运行时记忆**，点击**添加记忆**，在用户画像中写一条偏好，或在工作记忆中写一条项目事实。之后的每一轮都会注入它。

**一份档案。** 打开**工作区档案**，点击**新建档案**，保存一份简短的设计说明或检查清单。问题需要时，Agent 会检索档案。

**一个记忆空间。** 打开**记忆空间 → 概览**，点击**创建记忆空间**：

1. 选择 Provider。安装 CLI 后会出现本地默认的 Mnemon Native；第三方 Provider 需要先在[记忆空间页面](dsh-workbench.md#ui-在插件页中)启用。
2. 起一个范围明确的名称，例如“项目决策”，并说明其中应该保存什么。
3. 保持激活，对话才能读取它。

在空的存储根目录中，第一个 Mnemon Native 空间使用 Mnemon 的 `default` Store ID，同时保留你填写的名称与说明；其他 Provider 上的空间使用各自的 ID。接着点击**存入记忆**，写下稳定且不含机密的内容，点击**交给任务 Agent**；独立任务 Agent 会选择空间、去重并写入，回执写明存到了哪里。

**验证一下。** 打开**记忆空间 → 检索**，提一个具体的问题，点击**直接检索**。每条结果都保留所属记忆空间、分类、重要性与分数；需要时可以复制 ID。

![在已激活的记忆空间中直接检索](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/memory-recall.jpg)

也可以使用对话命令：

```text
/mnemon status
/mnemon recall <具体的问题>
```

<a id="start-4-在对话中使用记忆"></a>

<a id="start-3-在对话中使用记忆"></a>

### 3. 在对话中使用记忆

提一个依赖已保存内容的问题，让 Agent 自己判断是否需要记忆。回复完成后：

- 如果这一轮用到了记忆，会出现**本回合记忆**，展开后按工具列出读到和写入的档案与记忆，点击一条即在所在页面打开它；
- 回复下的脑形图标是**存入记忆**，打开可编辑的对话框，“取消”不会写入任何内容，交给任务 Agent 后会收到回执。

![一条回答用到了工作记忆、工作区档案与记忆空间，回合记忆栏列出读到的档案与记忆](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/chat-recall.jpg)

普通对话不会强制召回。当前请求、仓库文件与实时工具结果的优先级高于历史记忆。

<a id="start-5-选择记忆的组合方式"></a>

<a id="start-4-选择记忆的组合方式"></a>

### 4. 选择记忆的组合方式

点击记忆系统顶栏的齿轮，或选择**记忆系统 → 设置**。

![记忆组合面板](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/plugin-composition.jpg)

- **记忆来源**：运行时记忆、工作区档案与记忆空间，各有一个开关。关闭后停止它的上下文、工具与后台任务，但不删除数据。
- **增强**：主动记录默认关闭。
- **存储**：全局（默认）让所有工作区共用一个目录；工作区把每个工作区的记忆放在它自己的 `.mnemon`；集中存储把每个工作区放在同一个根目录下。**数据目录**在“默认”与“自定义”之间选择。两者的改动都不会搬移已有数据，各个范围的说明见[存储范围](dsh-configuration.md#存储范围)。
- **界面**（在 DSH 插件页的**记忆系统**页面中）：记忆系统可以在侧栏或会话标签页中打开，也可以开关对话中的两个控件。

开关与选择器立即生效，存储的改动需要点击**应用**。[界面指南](dsh-workbench.md#ui-在插件页中)介绍了每个页面，[配置参考](dsh-configuration.md)列出了它们背后的设置项。

<a id="capabilities-能力地图"></a>

## 能力地图

dsh-mnemo-weave 是 DeepSeek Harness（DSH）的记忆系统。它不把所有知识塞进同一个数据库，而是把高频上下文、完整的项目叙事和长期证据分开保存，由主策略决定它们如何进入每一轮对话，并用 Mnemon Native 提供长期记忆。

一句话判断：**每轮都要用的上下文放进运行时记忆，完整叙事放进工作区档案，跨任务需要的证据放进记忆空间。**

<a id="capabilities-能做什么"></a>

### 能做什么

| 目标 | 位置 | 如何执行 | 会改动数据吗 |
|---|---|---|---|
| 让偏好、约定和环境事实每轮可用 | **运行时记忆** | 宿主维护 `USER.md` 与 `MEMORY.md` 投影 | 会，确认后生效 |
| 保存完整的设计、调查、流程与交接 | **工作区档案** | 宿主管理 Markdown、检索、容量与修订 | 新建与编辑会；阅读与检索不会 |
| 在长期记忆 Provider 中创建空间 | **记忆空间 → 概览 → 创建记忆空间** | 由你选择一个已启用的 Provider | 会 |
| 决定任务 Agent 新建空间时用哪个 Provider | **记忆空间 → 新空间的 Provider** | 固定一个 Provider，或先执行宿主规则、再由任务 Agent 在合格候选中选择 | 保存设置时会 |
| 查找原始长期证据 | **记忆空间 → 检索 → 直接检索** | 各已激活空间以原生召回方式并行返回 | 不会 |
| 把证据整理成回答 | **记忆空间 → 检索 → Agent 查询** | 干净的任务 Agent 只拿到有界证据 | 不会 |
| 判断、去重、提炼并写入候选内容 | 回复下方或记忆空间页的**存入记忆** | 干净的任务 Agent 在宿主限定的工具、路径、锁与回执下工作，并给出回执 | 仅当 Agent 决定写入时 |
| 为多个空间生成标题与说明 | **记忆空间 → 概览 → 整理名称与说明** | 每个空间一个独立任务 | 只改本地目录元数据 |
| 把档案移出热容量 | **工作区档案 → 归档** | 宿主移动原文件，已归档资料仍可阅读 | 会 |
| 查看一轮对话用了哪些记忆 | 回复下方的**本回合记忆** | 按工具列出读到和写入的档案与记忆，每一条都在所在页面打开 | 不会 |
| 改变记忆的组合方式 | **记忆系统 → 设置 → 记忆组合** | 开关作用于之后的回合 | 只改配置 |
| 开关、使用、编辑与恢复 DSH 技能 | **记忆系统 → 技能管理** | Host 以文件哈希为界读写 `SKILL.md` 文件夹，保留每个版本 | 会，每次写入都留下版本 |
| 从真实对话中改进技能 | 开启自进化后的**技能管理 → 进化** | 任务 Agent 复盘结束的对话，提出建议并生成草案；草案先回测，再由你采纳 | 只在**采纳**时 |
| 测试技能 | **技能管理 → 评测** | 每个用例模拟运行一次，由评审逐项判定检查项 | 只改用例与回测记录 |
| 查找并安装技能 | **技能管理 → 市场** | skills.sh 搜索、GitHub 仓库、Agent Skills 网站与技能目录；每次安装前都可预览 | 会，在你确认之后 |

<a id="capabilities-三类记忆"></a>

### 三类记忆

| 记忆 | 适合保存 | 如何进入上下文 | 事实源 |
|---|---|---|---|
| **运行时记忆** | 高频偏好、协作规则与项目事实 | 每轮紧凑注入 | `runtime/memories.json`，Markdown 文件是投影 |
| **工作区档案** | 需要保留结构与来源的长篇知识 | 先检索，需要时读取全文 | `documents/index.json` 与受管理的 Markdown |
| **记忆空间** | 跨会话的事实、决策、实体与关系 | 从已激活空间召回有界证据 | Mnemon Native Store 或所选的外部 Provider |

三者各是一个独立的 Source 插件。运行时记忆与工作区档案使用本地存储；记忆空间通过 Provider 切换后端，不影响另外两者。外部 Source 也可以通过同一套公开契约加入。参见[架构设计](architecture.md)。

<a id="capabilities-策略与增强"></a>

### 策略与增强

每一轮由一个**主策略**组合。**增强**通过标准插槽为正在运行的主策略补充能力，可以同时使用。它们都在记忆系统的**设置**页中选择。

| 组件 | 作用 | 选项 |
|---|---|---|
| **分层策略** | 运行时记忆常驻；按需检索工作区档案、召回记忆空间；执行空闲审查与容量维护 | 任务 Agent 模型与空闲审查 |
| **主动记录** | 在回合中提示保留有用的事实，它是提示而不是自动记录器；新说法纠正旧条目时按该来源提供的修订操作更新，不做无关条目的清理 | 记录目标、记录指引与记录操作 |

切换策略不会搬移数据，一轮对话会保持它开始时的组合。这些选择如何保存，见[配置参考](dsh-configuration.md)。

<a id="capabilities-长期记忆-provider"></a>

### 长期记忆 Provider

本项目只支持一种 Provider：**Mnemon Native**，即官方本地 CLI 与 SQLite，提供完整图谱、精确写入与默认本地优先，作用范围为全局、工作区或自定义根目录。

**设置 → 记忆空间**页面保存它的服务设置与开关；记忆系统中的“记忆空间”页管理具体的空间。Mnemon Native 需要 Mnemon CLI，缺少 CLI 时没有其他 Provider 可以替代。参见 [Provider 指南](dsh-operations.md)。

<a id="capabilities-谁在工作"></a>

### 谁在工作

**宿主，确定性执行。** 状态、直接检索、内容与实体浏览、激活、运行时记忆的普通编辑、档案阅读与编辑都不需要模型，直接经过宿主的 schema、路径、权限、锁、修订、容量、超时与取消检查。

**独立任务 Agent。** 它们不复用主对话的历史，也不占用主对话的上下文窗口：

- **存入记忆**：判断价值、选择范围、去重、提炼并写入，给出回执；
- **Agent 查询**：根据有界的召回证据作答；
- **整理名称与说明**：为每个选中的空间运行一个标题与说明任务；
- **新空间的 Provider（智能选择）**：只有规则留下多个候选时才调用模型。

任务 Agent 默认跟随 DSH 新会话的模型，即最近一次在任意会话中选择的模型。分层策略页面“后台任务”中的**任务 Agent 模型**也可以改为跟随发起该工作的会话（与审查一致），或自定义 Provider 与模型，见[配置参考](dsh-configuration.md#后台任务-agent-的模型路由)。任务相互隔离，失败只显示在对应的空间或操作上，不会阻塞整个页面。

<a id="capabilities-出现在哪里"></a>

### 出现在哪里

| 位置 | 提供什么 |
|---|---|
| **记忆系统** | 状态、设置、运行时记忆、工作区档案、记忆空间与技能管理，以及每一个确认步骤 |
| **插件页** | 记忆系统入口和对话控件设置 |
| **对话** | 回合记忆栏、本回合技能提示、存入记忆，以及跳转到记忆系统的入口 |
| **Headless** | 相同的运行时注入、档案检索、记忆空间工具、工作区路由与受监督写入，没有 WebUI |
| **命令与工具** | `/mnemon` 命令，以及 Agent 使用的最小权限工具 |

<a id="capabilities-存储范围"></a>

### 存储范围

**全局**使用 `MNEMON_DATA_DIR` 或 `~/.mnemon`，本机各工作区共享；**工作区**使用 `<workspace>/.mnemon`，Mnemon Native 可以跟随它；**自定义**是位于你所选路径的全局范围；**集中存储**在同一个根目录下为每个工作区建立子目录，并可选择全局共享 `USER.md`。切换时不会移动、合并或删除原来的根目录。Mnemon Native 的 Store 身份不会随 DSH 工作区改变。各个范围的说明见[存储范围](dsh-configuration.md#存储范围)，根目录中保存什么见[存储模型](architecture.md)。

<a id="capabilities-明确不做什么"></a>

### 明确不做什么

- 历史记忆永远不会凌驾于当前指令、实时工具结果或仓库事实之上；
- Provider 之间的差异如实呈现，缺少图谱、删除或精确写入时不会伪装；
- Provider 凭据不会进入浏览器、任务 Agent 或备份；
- 关闭 Provider 不会删除远程数据，只清理本地目录，重连后重建；
- 切换存储范围不会迁移、合并或删除旧的根目录；
- 不提供跨本地文件与远程 Provider 的分布式事务。

<a id="ui-界面指南"></a>

## 界面指南

dsh-mnemo-weave 出现在三个地方：对话里能看到每一轮读到和写入了哪些记忆，也能把回复存入记忆；**记忆系统**用来浏览、检索和编辑已保存的内容，并在**设置**页组合记忆、修改存储；**插件**中的“记忆系统”页面负责界面设置。

| 位置 | 在这里做什么 | 如何打开 |
|---|---|---|
| [在对话中](dsh-workbench.md#ui-在对话中) | 查看一条回复用到的记忆与技能，一键打开；把回复存入记忆 | 每条已完成回复的下方 |
| [记忆系统](dsh-workbench.md#ui-记忆系统) | 在**设置**页组合记忆、修改存储与组件设置；查看状态；浏览、检索、编辑运行时记忆、工作区档案与记忆空间；管理技能 | 侧栏中的**记忆系统**、会话标签页，或顶栏的齿轮 |
| [在插件页中](dsh-workbench.md#ui-在插件页中) | 设置记忆系统入口、回合记忆栏与存入记忆按钮 | **插件 → 记忆系统** |

本页的录屏与截图来自 [v0.5.32 图集](https://github.com/omdsh-dev/dsh-mnemon/blob/main/docs/assets/webui-v0.5.32/README.md)：真实 DSH 0.2.1 WebUI 的浅色界面，预置的虚构项目 Lumen，回答、写入与回执都由真实的 DeepSeek 模型生成；等待模型的片段以 4 倍或 6 倍速播放，画面右下角会标出。嵌入由本机 Ollama 在 Mnemon 的默认地址提供，Mnemon Native 嵌入设置保持默认，因此每条记忆都有向量。技能管理的截图来自 [v0.5.34 技能管理图集](https://github.com/omdsh-dev/dsh-mnemon/blob/main/docs/assets/skills-v0.5.34/README.md)，项目相同，由脚本化模型作答。这些截图与录屏记录的是当时的界面：**记忆组合**与**存储**后来移到记忆系统的**设置**页，图中仍显示在插件的**记忆系统**页面上；本文其余部分按当前结构描述。

有两条规则处处适用：**开关与选择器改动后立即生效**，写入失败时控件恢复为已保存的值，并在旁边说明原因；**需要输入的值等待所在分组的“应用”**，有改动时才出现，并说明应用后会发生什么。

<a id="ui-回合记忆栏"></a>

#### 回合记忆栏

用到记忆的回复末尾会有一行**本回合记忆**，前面是记忆系统的脑形标识，后面是这一轮的召回、档案检索与写入次数。展开后每个工具一行：左边用平常的话写出工具做了什么，例如**工作区档案检索**、**记忆空间召回 ×2**，悬停可以看到工具本身的名称；右边列出它读到或写入的内容。

#### 存入记忆

![在回复下点击脑形图标，编辑候选内容，交给任务 Agent，收到回执后在记忆空间中查看新记忆](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/save.gif)

- 标题是**存入记忆**，下方一行说明这段文本会如何处理；**任务 Agent 就绪**标签表示任务 Agent 可以接手。
- **候选内容（可编辑）**预先填入整条回复，通常只保留要记住的那一句。**取消**不会改动任何数据。
- **保存到**选择写入位置：
  - **由 Agent 决定**：任务 Agent 能写入时的默认选项。**交给任务 Agent** 后，一个独立的任务 Agent 判断是否值得保存、选择合适的记忆空间、去重、提炼并写入，不占用当前对话。

  - 只有层已开启、组件在运行且没有关闭写入的位置才会列出。
  - 没有任务 Agent，或没有记忆空间 Provider 时，只要工作记忆在列，对话框默认选中**工作记忆**。完全没有可用位置时，对话框会说明，并且无法提交。

<a id="ui-记忆系统"></a>

### 记忆系统

![依次查看状态、运行时记忆、工作区档案、记忆空间概览与图谱，再用 Agent 查询得到带引用的回答](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/memory.gif)

记忆系统有六个页面：**状态**、**设置**、**运行时记忆**、**工作区档案**、**记忆空间**和**技能管理**。**设置**是记忆系统自己的页面，承载**记忆组合**与**存储**；其余页面的名称来自提供它们的组件，安装的 Source 也会以同样方式加入自己的页面。关闭 Source 或对应记忆层后，其标签页隐藏；重新开启后恢复。如果关闭的是正在查看的页面，会返回状态页。**设置**与状态页始终保留，已开启但未能运行的 Source 仍保留诊断标签页。顶栏显示连接状态与正在组合记忆的策略（例如“已连接 · 分层策略”）、服务器同步状态、存储范围、**刷新**与打开**设置**的齿轮；点击连接状态与策略会展开组合摘要，其中的**前往配置**同样打开**设置**页。**刷新**重新读取当前页面，所以各页面不再单独放置刷新或同步按钮。服务器同步状态常驻顶栏：图标区分已同步、同步中、失败与未配置，悬停显示上次运行的结束时间、拉取与推送数量或失败原因，点击在已配置时立即同步、未配置时打开设置页。见[服务器同步](dsh-operations.md#ops-服务器同步)。

面板宽度不超过 520px 时，标题与操作放在第一行，工作区选择器独占第二行。连接状态圆点、刷新、齿轮与已有的返回会话操作仍可用。远程只读与空闲审查暂停说明合并为“提示”摘要，点击可展开全文，再点一次收起；切换页面会保留展开状态。错误、组合诊断与重启提醒始终显示。更宽的面板继续直接显示完整提示。

记忆系统默认位于侧栏，回来时停留在原来的页面。从对话里的回合记忆栏打开时，页面会定位到那一条内容；在顶栏切换标签页则打开干净的页面。在**界面 → 记忆系统入口**中选择**会话标签页**，即可改为在会话内打开，页面完全相同。**返回会话**或 Esc 回到对话。

离开面板或隐藏它所在的浏览器标签页后，自动检查与轮询暂停。返回时刷新当前可见范围，保留仍属于该范围的草稿；已经开始的操作可以继续完成。技能栏先让对话渲染，再由同一会话的各回合共用一次活动读取；没有新回合时，切走再切回也会保留空结果。尚未完成的复盘会在会话再次可见时继续跟踪。技能编辑与手动复盘会更新已有回合的技能栏；历史暂时不可读时，返回会话后仍会重试。

<a id="ui-状态"></a>

#### 状态

![状态页：记忆引擎、每个记忆组件一张卡片、正在运行的 Provider 与存储域](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/memory-status.jpg)

第一行每个组件一张卡片：先是记忆引擎及其版本，然后是各个 Source 保存的内容，最后一张是存储域——范围、读写根与合计大小，路径在悬停时显示全文。记忆 Provider 的连接状态不在这里列出：它在**设置 → 记忆空间**中逐项显示。各区域独立加载，一处失败不会遮住其他内容。

状态条下方是**记忆活动**：宿主最近记录的记忆读写与子任务，最新的在前，每行给出发生时间、所属活动流（工作区或工作准则）、来源与操作、结果，以及返回条数、耗时或已提交写入数。结果取自活动的结构化字段，区分有结果、无结果、跳过、已提交、未确认与失败；跳过另标预算用尽、未执行或不可用。它读取与服务器同步相同的不可变事件，因此其他机器同步后显示同样内容，且不含查询词、正文、路径或错误原文。页面每 5 秒重读一次，最多显示最近 50 条。

列表右侧的**删除活动记录**在确认后删除所选工作区与工作准则两个活动流当前已有的全部记录，不只是页面列出的条目。记录被实际删除，每个活动流只留一条清空事件标明它现在从哪一刻开始；这条事件随同步传输，服务端据此丢弃被取代的批次，另一台机器在**同步全部**后同样删除这些记录。清理之后产生的活动照常显示，记忆内容和会话历史不受影响。只读模式下该动作不可用。

再往下是**运行日志**：宿主最近记录的操作，最新的在前，失败行标红并展开原因链。传输失败会写成 `fetch failed — connect ECONNREFUSED 127.0.0.1:8787` 这样带原因的一行，而不是只有 `fetch failed`。日志可按**只看失败**筛选，并显示失败与警告条数。它只保存在宿主进程内存中，最多保留最近 200 行，重启后从空开始，不同步也不写入 Pack。同步一次只写开始、结束和实际有变化的范围各一行，未变化的范围分别汇总为一行。

工作台不在顶部为失败显示红色横幅。同步失败、状态读取失败、空闲审查失败与审查配额暂停都写入**运行日志**，原因和细节在那里按时间排列；工作区保持用于阅读记忆。空闲审查失败时，日志先给出一行带运行 id 的失败，再逐条列出本次已提交、未回滚的写入，可以照着核对。

只有记忆需要处理时，页面上方才会出现带**前往配置**的提示：

- **记忆未生效**：没有主策略在运行，对话会在没有记忆的情况下继续。
- **所选主策略没有运行**：暂时由另一个策略组合记忆。
- **最近的组件变更没有生效**：继续使用之前的组合。

这些**前往配置**，以及已关闭或未运行的记忆层页面上的**前往配置**，都打开记忆系统的**设置**页。

**检查版本**只读取信息：它会说明 Mnemon CLI 是缺失、最新还是可更新，并给出可复制的 npm 命令；还会列出每个子包的已安装、已发布与锁定版本。本地构建更新按[安装与热重载](usage.md#deepseek-harness)执行。CLI 与组件状态见[版本检查与更新](dsh-operations.md#ops-版本检查与更新)。

<a id="ui-运行时记忆"></a>

#### 运行时记忆

运行时记忆是每一轮都会注入的紧凑上下文。**用户画像**（`USER.md`）记录你是谁、你的偏好与协作规则；**工作记忆**（`MEMORY.md`）记录项目事实、环境、决策与经验。每张卡片显示已用大小与上限。从回合记忆栏打开时，本回合写入的条目带有高亮边框，见[上文的纠正示例](dsh-workbench.md#ui-回合记忆栏)。

- 条目按时间倒序排列，可以按目标与文本筛选；编辑旧条目不会改变它的位置。**添加记忆**打开添加运行时记忆的对话框。
- 条目应简短、相互独立、会被反复用到；临时进度和原始日志不应放在这里。
- 工作记忆条目可以限定 git 分支，只有会话工作区处于这些分支时才会注入；页面和磁盘上的文件不受影响。
- 工作记忆达到上限时，宿主先把其中的条目归档到记忆空间，保留上限约 70% 以内最重要的条目，再添加新条目。没有能接收它们的记忆空间时（例如没有 Mnemon CLI，也没有其他 Provider），未保留的条目改为移入数据目录下的本地归档 `runtime/archived/MEMORY.md`。

<details>
<summary>编辑、容量与分支细节</summary>

“编辑”和“移除”在所属目标中按完整内容匹配条目，因此可以只修改简短的 `X`，而不影响 `EGO_LINUX_CHROME`。同一目标中完全相同的条目无法区分，会被拒绝且不改动数据。

容量归档移动的是原始条目。某一批路由失败或返回无效提案时，这一批会写入符合条件的默认记忆空间或第一个符合条件的空间，摘要中会记录原因。当前回合创建或激活的空间，在激活并支持写入后也可以接收归档。存在能接收归档的记忆空间、但当前回合无法写入时，已有条目保持不变，待添加的条目也不会保存；排除原因后在新回合重新提交即可。完全没有能接收归档的记忆空间时，未保留的条目改为移入本地归档。

Agent 写入用户画像时，`branches` 必须省略或为空。对工作记忆执行替换时，`branches: []` 会清除分支限定，省略则保持原样。提示词里只呈现条目正文，不带重要性、时间跨度或分支名；分支限定只影响哪些条目被投影。参见[投影格式与上限](architecture.md#storage-事实源和投影)。

</details>

<a id="ui-工作区档案"></a>

#### 工作区档案

![工作区档案：从回合记忆栏打开，目录中选中“架构决策：事件摄取改用队列”](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/memory-documents.jpg)

工作区档案保存完整的叙事：设计、调查、流程与交接。请先选择 DSH 工作区；即使使用全局存储，档案也属于某个工作区。

对话工具按会话工作区（`session.header.cwd`）确定工作区档案的归属。普通子代理继承父会话工作区；改变命令目录，包括委派任务的初始目录，不会改变档案目标。在项目 A 的会话中让子代理到 B 目录执行命令，档案仍进入 A 对应的存储。要为 B 建档，请在 B 的 DSH 工作区新开会话，或在记忆系统选择 B 后使用档案的手动管理。`workspace` / `workspaces` 按此身份选择独立存储；`global` / `custom` 则可能共用物理存储。

- 在**活跃档案**与**归档**之间切换；阅读器保留标题、检索描述、来源、所属工作区、修订、哈希、大小与完整 Markdown。
- 工具栏的**工作区**选择按档案写入时所属的工作区筛选：默认**全部工作区**，可以只看某一个工作区，或只看未记录工作区的旧档案。选项右侧给出该工作区的活跃与归档数量，检索与活跃/归档切换都在所选范围内生效；对话工具默认仅在当前工作区检索。
- 检索会匹配标题、描述与正文；列表按创建时间倒序，更新旧档案不会把它移到最前。
- 项目中的源文件永远不会被修改，档案是受管理的副本。
- 详情标题旁的**删除**会在确认后永久移除活跃或归档的托管副本及其索引记录。无需模型或归档任务，不会建立记忆空间冷索引，已有记忆空间条目保持原样；完成后刷新列表和容量。如果确认期间索引或托管文件发生变化，请取消、刷新并核对最新内容后重试。
- 新建资料时可填写来源路径并将正文留空，保留指向仓库原文的引用。
- 未记录归属的旧资料可在详情页选择**归入当前工作区**，之后可在该工作区的对话里检索。
- 归档直接移动托管文件，仍可在**已归档**中阅读。旧冷索引保留原有引用。

会话沉淀在出现有依据的新候选时运行。已验证的经验可以进入正式记忆，资料或工作准则的增改需要明确的用户意图。

<a id="ui-记忆组合"></a>

#### 记忆组合

**记忆组合**是记忆系统**设置**页的第一节。

- 策略由 Core 内置，不是可切换的组件：**分层策略**让运行时记忆常驻，按需读取工作区档案与记忆空间，并执行空闲审查与运行时容量维护。它的页面提供任务 Agent 模型与审查参数。

- 下面是**记忆来源**与**增强**，每个组件一行，显示状态、开关，有自己设置的组件还有齿轮。标签写明这一行依赖的组件或依赖它的组件，点击即可打开对应页面。
- 只有记忆没有按你的选择组合时，才会出现一行问题说明，并给出能解决它的那个开关。

每个开关都作用于之后的回合，已经开始的回合保留原有的 View。打开一个组件时，它依赖的组件会一起打开，不能与它共存的组件会被关闭；关闭一个组件时，依赖它的组件也会关闭；选择一个主策略时，其他主策略会被关闭。最后一个运行中的来源不能关闭。开关影响到其他组件或改变了组合方式时，DSH 会弹出提示，并提供**撤销**。

- **服务器同步**可保存服务器地址和同步口令。点击 **同步全部** 后，增量同步工作准则、活动记录和全部参与同步的工作区，并在按钮下方显示当前阶段、步数、正在同步的范围、已传输文件数和已用时。见[服务器同步](dsh-operations.md#ops-服务器同步)。
- **记忆整理**用来整理本机已有的工作准则和档案。**整理记忆**让 agent 给出方案，**整理要求**写下你的目标，只有接受后的方案才会执行，可以整份执行，也可以只执行勾选的操作。每一步的说明见[记忆整理](dsh-operations.md#ops-记忆整理)。
- **数据目录**：在**默认**与**自定义**之间选择，这一行只显示记忆正在使用的一个目录。默认目录是 `MNEMON_DATA_DIR` 或 `~/.mnemon`；自定义时填写绝对路径或以 `~/` 开头的路径，集中存储下它是根目录。输入框留空只表示尚未填写，回到默认目录请选择**默认**。 宿主提供 DSH 原生选择器时，**选择目录**会填入同一份草稿；取消不改动草稿，保存仍需点击**应用**。其他宿主继续手动输入。
- 范围与目录一起点击**应用**，应用前会说明后果：记忆改为读写新位置，已有数据不会被移动、合并或删除。

![备份与迁移：导出的 ZIP 在安全导入前的预览](https://raw.githubusercontent.com/omdsh-dev/dsh-mnemon/main/docs/assets/webui-v0.5.32/zh-CN/plugin-backup-preview.jpg)

**备份与迁移**把当前数据目录中“存储”所列组件的数据导出为 ZIP，不包含第三方 Provider 的数据与凭据。导入时先显示校验后的内容预览，**安全导入**把它合并到当前目录。参见[备份与恢复](dsh-operations.md#ops-备份与恢复)。

**界面**是插件页中**记忆系统**页面的唯一一节。

#### 随附组件

在**记忆系统 → 设置 → 记忆组合**启停和配置随附组件。DSH 插件页管理整个记忆系统。

<a id="ui-查看的工作区与执行的工作区"></a>

### 查看的工作区与执行的工作区

| 概念 | 由谁选择 | 影响 |
|---|---|---|
| **查看的工作区** | 记忆系统顶栏 | 页面显示和编辑哪个 `<workspace>/.mnemon` |
| **执行的工作区** | 当前对话的工作目录 | 对话工具、命令与生命周期钩子使用哪个根目录 |

你可以在项目 A 的对话中查看项目 B。对话仍然作用于 A；从记忆系统发起的存入记忆、Agent 查询、整理名称与说明与档案归档，会以限定于 B 的任务 Agent 运行。远程 Provider 的命名空间不会随 DSH 工作区变化。全局与自定义存储只对应一个根目录，无需对齐。

<a id="ui-交互约定"></a>

### 交互约定

记忆相关的界面在各处遵循同一套约定：

- **一个标识**：对话中的回合记忆栏、存入记忆按钮与侧栏的记忆系统都使用脑形标识；DSH 的数据库形状图标表示用量，与记忆无关。
- **一个名称，一份回执**：写入长期记忆的操作在各处都叫**存入记忆**，由任务 Agent 或你在对话中选择的位置完成，并给出同样的回执。
- **名称优先于标识符**：界面用标题、内容与空间名称指代记忆，不显示原始 id 或路径；需要时卡片上的**复制 ID** 仍然可用。
- **统一的控件**：搜索框、选择项、开关与对话框按钮使用 DSH 的输入框、选择器、开关与描边“取消”；菜单与提示显示在对话框上方。
- **刷新只在顶栏**：**刷新**重新读取当前页面；各页面不再单独放置刷新或同步按钮。
- **操作的轻重**：主要操作使用 DSH 主按钮，编辑等次要操作使用描边按钮；红色只用于删除、断开、归档与忘记。
- **说明一行**：各页与各分组的说明控制在一行以内，细节放在对应的指南中。
- **状态只列运行中的部分**：状态页列出正在运行的 Provider，其余汇总为一行，并提供前往配置。

另外：记忆空间的开关只决定 dsh-mnemo-weave 是否读取它，与 Mnemon CLI 的默认 Store 无关；删除 Mnemon Native 空间需要确认，外部空间使用“断开”，不会改动 Provider 中的数据；反复点击（包括选择已选中的值）都不会让页面变空白。
