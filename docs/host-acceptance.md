# 宿主验收

本文列出目标通过条件。交付证据与迁移待办见 [当前状态](status.md)。

验收使用隔离状态目录、专用 Mnemon Store 和可识别的测试工作区。启动方法见 [根目录 README](../README.md)。各宿主配置同一台本机 Server、同一测试工作区和不同 Host ID。使用服务令牌连接；管理凭据留在管理端。记录宿主版本、测试场景、实际结果和脱敏证据。

## 宿主接入

| 宿主 | 代码与运行方式 | 实机验收 |
|---|---|---|
| DSH | `plugins/dsh-mnemo-weave`。导入插件，在真实会话检查提示注入、工具与界面 | 检查工具注册、提示注入、界面和写入任务 Agent |
| ChatGPT 桌面 | `packages/adapters/chatgpt` 与本地插件。使用 local-only command hooks，注入通过 `hookSpecificOutput.additionalContext` | 检查真实会话、工具结果变体、`SessionEnd` |
| ZCode | `packages/adapters/zcode`。启用 hooks，验证 `additionalContext`、MCP 和 `Stop` 的最终答复映射 | 检查真实会话。宿主缺少独立会话结束事件，`Stop` 只表示一轮结束 |

配置生成与取证入口位于 `tests/support/`。ZCode 使用 `zcode-acceptance-setup.ts` 和 `zcode-acceptance-collect.ts`；ChatGPT 使用 `chatgpt-acceptance-setup.ts`。DSH 插件导入与连接见 [DSH 适配](ui.md#dsh)。

ZCode 工作区的配置和采证命令在构建后运行：

```powershell
node dist/tests/support/zcode-acceptance-setup.js <workspace> http://127.0.0.1:4317 <service-token> zcode-host
node dist/tests/support/zcode-acceptance-collect.js <state-dir> zcode-host
```

先生成配置，再运行真实会话，最后采证。ChatGPT 使用配置生成器输出的本地工件，在目标宿主中安装并审查。目标验收中，测试工作区通过 operator 登记，两台设备用不同的本地路径绑定同一个工作区 ID，并确认两台设备读取同一个档案 ID 与版本。

## 工具注册与注入判据

注册方式、工具名和触发事件以 [实现与契约](implementation.md#宿主工具注册) 为准。工具可见与注入成功分别采证。

- **DSH**：启用会话插件，在真实会话检查[目标清单](implementation.md#dsh-原生工具)中的原生工具。卸载后这些工具均消失，重新加载后各只出现一次。用同一轮的两个模型步骤核对 `mnemo-weave:rules` 内容相同。修改准则后，同轮保持原内容，新轮获取更新。
- **ZCode**：检查工作区 `.zcode/config.json` 的 `hooks.enabled` 和 `mcp.servers.mnemoweave`，或使用插件清单。分别记录 MCP `tools/list` 和 `SessionStart`、`UserPromptSubmit`、`PostToolUseFailure` 的 stdout。成功注入从顶层 `additionalContext` 读取。成功工具结果和 `Stop` 不产出注入。
- **ChatGPT 桌面**：检查本地 command Hook 和 stdio MCP 服务分别启用。记录 MCP `tools/list`，再验证 `SessionStart`、`UserPromptSubmit` 和可识别的失败工具结果从 `hookSpecificOutput.additionalContext` 送达。成功工具结果、`Stop` 和 `SessionEnd` 不产出注入。
- **共同检查**：轮次相关工具先验收 DSH 原生接入。ChatGPT 桌面和 ZCode 暂不验收 MCP 会话与轮次绑定；只提供已验明不依赖绑定的能力。关闭 MCP 后，宿主注入仍可独立交付完整准则。完整内容放不下时验证报告失败并继续回合。确认档案与正式记忆只由工具返回。

## 共同判据

- 已运行的 Server 可复用。冷启动或并发启动只有一个 Server。令牌错配保留现有进程。
- 在同一测试工作区的三个真实会话中检查启用准则按完整条目送达，核对 10,000 UTF-8 字节容量及超限拒绝；切换工作区后准则集合不变；工作区档案检索只返回该工作区的条目并受6,000 字符正文预算和调用次数上限约束。记录注入往返与截止行为。
- 在两个工作区各建一条同标题档案。切换管理页工作区时只显示所选工作区的列表、搜索和容量。会话工具传入另一个工作区的档案 ID 时返回 `NOT_FOUND`，即使该 Host 有权在管理页查看那个工作区。
- 验证本机没有工作上下文写入入口，准则注入不携带宿主临时状态。宿主无法提供任务所需的会话片段时，依赖该片段的动作跳过并记录原因。
- 在同一工作区打开第二个会话，确认能读取第一会话创建的档案，任务只按需读取其来源会话。无工作区会话调用档案工具得到 `WORKSPACE_REQUIRED`，仍能使用正式记忆；管理页选择工作区后可写档案。
- 在工作区 A、工作区 B 和无工作区会话中，使用同一查询和正式记忆读取权限，核对可读取的条目及历史一致。检查工作区名称只进入查询文本，宿主发送一次召回请求；没有工作区名称时原样发送。工作区档案仍按工作区授权隔离。
- 在两个工作区的会话请求保存相同正文，只出现一个正式记忆逻辑 ID，第二次返回原 ID 和条目版本。分别验证只授权 `rules`、`formal-memories` 或 `workspace-archives:11111111-1111-4111-8111-111111111111` 的设备，每台只能同步获授权的流。给写入条目附加 `scope` 或 `stream` 时返回 `INVALID_INPUT`。
- 隔离演练同时包含准则、工作区档案、旧项目范围的正式记忆及已撤回条目。核对迁移前后逻辑 ID、修订、版本、哈希、关系、撤回状态与设备授权。旧客户端收到 HTTP 409 和 `SYNC_PROTOCOL_MISMATCH`。各同步流重新取得快照，并且只推进各自游标。未处理队列必须阻止切换。验证开放写入前可成套恢复。
- 恢复演练：在隔离目录验证同一批次的治理库与 Provider Store，以及被选择的技能文件、历史、草案和回测。核对备份清单及哈希，确认凭据、宿主会话全文和本机绝对路径绑定未导出。验证损坏文件和技能重名时保留现用数据。
- 召回诊断核对四类环境：嵌入服务不可达、服务可达但配置的模型不可用、只有部分记录具备向量、恢复后实际召回。每类记录 `GET /v1/diagnostics/embeddings` 的 `serviceAvailable`、`modelAvailable`、`embedded/total`、`recallMode` 与 `lastError`，并与真实召回结果对照。
- 空闲复盘：活动不足或不足 30 秒空闲时不启动；达到阈值后验证每次最多变更一条准则并新增一篇档案。档案先查重，自动任务不能更新或归档已有档案。核对冷却、会话次数上限、分别回执和无正式记忆写入。
- 主动召回：验证首查、第二个不同查询、同查询重放、关系扩展和全文读取各自的限额。关系起点须来自本轮直接召回。用中文和含代理对的正文验证字符计量。
- 请求超时或 Server 不可达时，宿主回合继续执行；支持注入诊断的界面应可解释缺失结果。
- DSH 主会话请求记忆时启动受限写入任务 Agent。通过检查的新增产生实际发布回执，完全重复返回已有回执，依据不足进入人工审核。修改任务输入验证越权动作、伪造目标、过期版本和不同载荷复用同一幂等键均被拒绝。撤回要求用户明确指定目标。通用 MCP 和无委派能力的宿主只返回候选回执。
- 验证正式记忆写入在远端排队、结果未知和本机尚未应用时不返回发布成功。恢复后相同任务动作得到原回执。空闲复盘部分失败时，只重试未完成的信号。
- 验证准则、工作区档案和正式记忆的编辑缺少基准版本时拒绝，提交已过期的基准版本时返回 `VERSION_CONFLICT`，草稿可保留。
- 记录事件来源与会话绑定。遇到宿主事件缺失或工具结果格式不明确，按实际表现登记。

## 容量与快照验收

- 两台设备并发写入使同一工作区超限，远端拒绝超限写入。再分别验证直接归档、提炼后归档、提炼待审及来源版本冲突。确认两台设备与快照恢复所得的档案状态、版本和活跃用量一致。
- 中断快照重建，确认本机仍读取旧状态和旧游标。恢复并完整校验后，目录或工作副本与游标一次切换。
- DSH 用长档案验证搜索与分段读取共用每轮四次额度，单次正文不超过 6,000 字符。档案版本变化后旧游标失效；用户界面仍可读全文与历史。
- 使用同一 Host 下的两个 DSH 会话及同一会话的两个轮次，验证工具从执行上下文取得可信绑定，额度和不留存标记各自生效。正式记忆召回按 Mnemon `confidence` 映射相关性，缺失时为未知。

## 主动记录工程经验验收

- 在 DSH 完成一次有可复用结论的工程验证，用户不额外说「记住」。检查工具说明提示主模型主动记录，宿主能核对本轮测试、实验或源码证据，正式记忆保留适用条件、观察和做法。以临时进度、工作区专有路径、原始日志和已存在等价记忆作为对照。
- 验证伪造或跨轮证据引用被拒绝。每轮第二条模型主动请求不创建新任务，重放和超时继续查询原回执。「本轮不留存」时既不委派也不提交候选。
- DSH 原生工具和 MCP 工具说明共用同一份经验指引。两个桌面宿主须先验证可信会话与轮次绑定，才验收主动候选提交。检查 MCP 候选回执不会显示为已发布。

## 任务与技能验收

- 达到空闲复盘阈值后标记「本轮不留存」，确认该轮不计分、不进入复盘证据。验证该轮模型调用 `remember`、准则变更和档案写入均返回 `UNAUTHORIZED`，不启动任务、不提交候选或资源变更；用户单独确认保存回复仍可提交。模型路由不可用、必要会话证据缺失或 DSH Agent Teams 暂停时，显示跳过原因且不扣减尝试次数。
- 使用长会话和长档案发起任务，核对总证据、单档案、输出和截止上限。预览显示实际采用的证据范围。超时后，已提交动作仍可查原回执。
- 整理预览默认无勾选。确认部分动作时只执行被选中的项。混合编辑、重复和版本冲突时核对逐项回执，重放不重复写入。
- 自动采纳开启后，以同一设备同一天的三个有效草案验证只启动两个自动任务。同一草案重复发起复用任务，同一技能的并发请求串行。超过 7 天的草案不自动采纳，仍可查看。

## 档案提炼验收

- 以一篇包含本地路径和通用排查方法的档案发起提炼。草稿应保留排查方法，完整预览应说明共享范围。关闭或放弃草稿时，正式记忆和同步流均无新增。显式确认后核对正式记忆正文与预览一致，源档案版本与状态不变。
- 让源档案在预览后编辑或归档，确认提交返回 `VERSION_CONFLICT`。移除源读权限后确认拒绝发布。模型工具和空闲复盘不能触发同一流程。
- 分别覆盖同文重复、转人工审核和同步结果未知，重放确认只得到同一任务的回执。另一台有正式记忆读权限、无该工作区权限的设备可以读取确认共享的正文；正式记忆的同步记录和详情不暴露源档案元数据。

## 通用界面验收

在每个宿主实际提供的用户入口中，核对 [记忆界面设计](ui.md#通用界面) 的权限、版本冲突、草稿保留和回执状态。对宿主未提供的入口记录能力缺口，MCP 工具调用成功单独采证。对已提供的档案提炼或回复保存入口，检查用户确认前没有发布动作。
