# Host 事件与自动注入契约

状态：HOST-03/04 为 Accepted；以下字段名、归一化方式与测试组织是自有工程草案（Proposed），不冒称任何上游 Host 已提供同名 API，也不冻结数据库 Schema。与 `host-integration-evidence.md`、`identity-and-offline-access.md`、`recall-and-view.md` 配套使用。

## 必需事件集合（Accepted）

三个目标 Host 均须接入会话开始、会话结束、用户消息、助手最终答复、工具完成结果（包括成功及失败）。不采集隐藏推理或逐 Token 输出。原生事件缺少某项时明确登记缺口，不用另一种事件的名称假充覆盖；必需入口不足仍阻塞对应 Host 首版验收。

实现状态（WP5）：事件信封 Schema、按 (hostId, eventId) 的稳定去重（同 ID 异内容 IDEMPOTENCY_CONFLICT）、选择性保存默认规则与 7+90 天保留周期已实现（`HostEvent` 契约与 `SessionEventStore`）。崩溃中断事件以 `inferred: true` 标注。适配器接线与注入执行属 WP7。

“可采集”仅表示适配器能收到并规范化事件。重要性筛选决定是否保存正文；候选提炼、审核和正式写入是后续独立阶段。普通选存材料执行热存 7 天、随后归档 90 天规则，受保护证据除外。不得把本要求实现为无限保存所有会话。

## 事件信封建议（Proposed）

| 字段 | 语义及校验 |
|---|---|
| protocolVersion、adapterVersion | 自有契约版本与产生事件的适配器版本；不支持的必要字段/主版本明确拒绝 |
| eventId | 跨重试稳定，绑定已认证 Host 身份去重；同 ID 不同内容返回冲突，不静默覆盖 |
| sessionId、turnId | 原生标识或稳定映射；原生无 turnId 时说明推导方式，不伪称原生提供 |
| projectId | 已登记的稳定项目身份；不能凭目录名称推断，不因事件正文声称属于某项目就自动授权 |
| kind | 自有归一类型：session.started / session.ended / message.user / message.assistant.final / tool.completed |
| occurredAt、receivedAt | 原生发生时间与 Bridge 接收时间分开；不靠客户端时间决定权限或覆盖先后 |
| sourceRef | 原始事件/工具调用的可追溯标识与证据类型；无稳定原生标识时保留映射依据 |
| payload | 允许类型的内容、工具调用身份和成功/失败状态；不得携带隐藏推理、密钥或无关的环境转储 |

调用方身份由配对凭据和通道认证确定，不信任 payload 中的 hostId。相同工具调用的成功/失败按真实终态记录；重试是新的尝试或独立结果，不把失败覆盖成成功。同一输出经 Hook 和 MCP 重复送达时按稳定来源身份合并，缺少确定依据时不凭相似正文误合并。

进程崩溃不等于正常会话结束。恢复时可以产生显式标注为推断的中断事件，但不能冒充已观察到的原生结束事件。助手最终答复与工具输出分别标明来源，不能把工具结果归为用户事实。

## 选择性保存和离线边界

在持久化前执行事件类型、身份、作用域和保存策略检查；正文筛选与最小去重元数据分开。只有已选择保存的内容才进入普通 Session 保留周期。需要作为候选证据的内容须建立受保护引用，正文不能先清理再留下无法追溯的证据 ID。

离线可排队候选、事件、版本及关系意图；它们不代表已审核或已正式写入。读取许可过期但本地身份仍有效且未明确撤权时，可继续接收新提供内容，不读旧记忆补全。明确撤权后未上传意图隔离保留，不自动提交。重连后由 Server 重验权限、版本基线和审核。

## 记忆不可用时继续普通任务（Accepted）

Bridge 不可用且无合法可读本地副本时，Host 明确显示记忆不可用并允许普通任务继续，不得显示“已加载”。不得注入已知撤权、许可过期或损坏的副本，也不把空结果包装成查询成功且没有相关记忆。

恢复后重试读取；新获得的上下文生成新的不可变 View，只能通过实际支持的后续注入入口交付，不声称已影响过去完成的模型步骤。恢复不会自动解除撤权或续期旧许可。合法离线副本仍可按既定读取许可与陈旧标记规则使用。

关键 Pinned 超出预算保留明确异常，不能用本条解释为可以静默忽略关键约束。运行时某次临时故障允许普通工作继续，也不意味着一个永久缺少必需接口的 Host 可以通过首版验收。

自有结果建议记录 status（injected / unavailable / denied / budget_exceeded）、reason、viewId（仅真实生成并交付时）、数据时间及是否使用本地副本。Host 无可靠回执时仅记录“已交付”，不能宣称模型已使用或遵循。

## 验收场景

| 场景 | 必须观察的结果 |
|---|---|
| 每个 Host 的核心闭环 | 原生触发六类入口：开始、结束、用户消息、助手最终答复、工具成功、工具失败；身份/会话/来源正确 |
| 重复与崩溃 | 重送不重复保存或提炼；ID 内容冲突可见；强杀不伪造正常结束 |
| 采集与审核分离 | 普通无价值正文可不保存；选存事件不会直接进入正式 Provider |
| 不可用 | 停止 Bridge 且无合法副本，明确提示后普通任务仍可继续，无虚假注入记录 |
| 恢复 | 重连重新校验权限，生成并交付新 View；旧模型步骤的历史不被改写 |
| 权限和预算 | 撤权/过期/损坏正文均不进入注入；关键 Pinned 超限仍显式异常 |

## 前台等待上限（Accepted：HOST-06）

普通自动注入默认最多等待 2 秒，优先本地检索；Host 自身限制更短时服从更短值。上限覆盖该次前台准备和交付等待，不能对每个子步骤分别重新计算 2 秒。主动 Recall 和后台模型任务保留各自预算，不将后台模型的 60 秒单次上限套用到普通注入。

截止时若尚无合法可交付结果，明确显示记忆不可用/准备超时，按 HOST-04 允许普通任务继续，不记录为成功注入。较慢结果只能在后续实际支持的入口重新校验授权、许可和任务关联后交付为新 View；不得向已结束的回调补写或声称已影响过去的模型请求。不能为了赶上截止时间省略权限、完整性或关键 Pinned 预算检查。

工程验收应覆盖本地命中、远端延迟、截止后返回、Host 更短期限以及截止期间撤权；验证前台不会因后台重试持续阻塞，也不会把迟到结果错误注入另一个 Session/Turn。计时与截止控制建议使用单调时钟（工程建议，非新增业务决策）。
