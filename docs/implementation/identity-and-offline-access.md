# 身份、撤权与离线访问规格

状态：已确认原则和第三至第六批决定的细化。凭据具体算法、配对协议等仍待细化，不将其假定为已接受。

## 三个独立判断

| 判断 | 含义 | 不能推导出的权限 |
|---|---|---|
| Host 身份验证成功 | 请求来自已登记的 Host | 不代表可读全部项目、可继续使用过期许可或具备审核权限 |
| 读取许可有效 | 在 Server 授予的范围和有效时间内可读取本地正式副本 | 不代表可批准正式写入或自动更新版本基线 |
| 接收本地意图 | 允许持久化用户/Host 新提供的待处理内容 | 不代表已通过 Server 授权、审核或持久化成功 |

不得用一个 authenticated 布尔值替代上述判断。组件能力声明也不构成授权。

## 首次 Host 配对

1. Host/Adapter 请求配对；尚未确认的请求不能访问记忆或建立已授权会话。
2. 用户确认 Host 身份并分配权限。AUTH-05 已选择在配对时明确授予当前及未来全部项目；Global 另行选择。授权记录必须能表达这一通配范围，而非维护一个无法覆盖新项目的静态列表。
3. Bridge 登记独立 Host ID 并签发绑定该身份的凭据；不同 Host 不共享一个通用令牌。
4. 后续会话通过该凭据建立上下文，不要求每个 Session 再次人工配对；新作用域、撤权或失效凭据不能靠重新打开会话绕过。

配对请求的单次凭证、有效期、确认通道及凭据轮换在协议与配置文档中明确；不能假设 DSH/Codex/ZCode 都提供同一种安装或后台委托 API。

## 离线状态与行为

| 状态 | 正式副本读取 | 新意图入队 | 已有队列 |
|---|---|---|---|
| 身份有效、读取许可有效、未收到撤权 | 授权范围内允许；副本状态异常仍受同步恢复规则限制 | 允许候选、事件、版本和关系意图入队 | 持久化保留，联网后重验 |
| 身份有效、读取许可过期、未收到明确撤权 | 禁止；不以缓存/旧 View/历史接口兜底 | 允许仅写入新提供内容，不读取旧记忆来补齐意图 | 保留，不能显示为正式成功 |
| 收到明确的 Host/Bridge/作用域撤权 | 立即停止受影响读取 | 被撤权身份/范围不再接受为可提交操作；不可沿用 AUTH-03 | 未上传意图隔离保留，不自动提交 |
| 无法验证本地身份 | 禁止 | 不按合法 Host 请求接收 | 原数据保留，不向未验证请求者暴露 |

读取许可默认 1 小时，由 Server 配置和续发；Bridge 不能自行延长。明确撤权具有优先级，不等待剩余许可到期。已返回给 Host 的上下文不可能由 Bridge 强制让模型“遗忘”；授权边界必须保证此后的读取、重新注入及操作都被拒绝，不能作出收回已交付信息的承诺。

许可到期后的新内容入队仅表示本地接收，不能基于过期副本自动检索来源、刷新 expectedRevision 或推导“最新版本”。原意图自带的明确基线应原样保存；缺少必要信息时保留待补充/待 Server 判断，不猜测。

## 撤权后保留副本

AUTH-02 已选择保留数据，而非后台清理。被撤权数据的正文、索引、缓存及已物化 View 都必须停止服务；“保留文件”不意味着还能通过搜索、历史、诊断、日志或其它 Host 绕过读取授权。

重新授权后不能直接把旧缓存标为当前：先验证身份、权限范围和新读取许可，再按既定同步/校验规则恢复。旧副本可复用，不强制重新下载全部正文；是否可直接复用必须有一致性和授权证据。

被撤权的本地意图保持隔离，重新授权后也不能静默补发，需明确恢复动作并由 Server 再验权限、幂等、基线与审核。队列隔离不能丢失原意图身份和证据，也不删除远端正式记忆。

## 实现边界

Bridge/Server 的正常接口授权不等于操作系统级文件保密。STORAGE-01 已明确：正式副本和待提交队列的 SQLite 不额外加密，依赖用户级文件权限及用户自行配置的磁盘加密。不得引入应用层数据库加密作为首版运行前提，不将用户自管的磁盘加密描述成程序已实现的功能。不得宣称可以抵抗已经控制同一用户会话或系统管理员的进程。

Host 撤权、Bridge 撤权、项目作用域撤权应分别可表达。涉及多个未撤权 Host 共用同一 Bridge 副本时，不能因一个 Host 失权而误删或阻断其它仍授权 Host 的合法数据；每次访问都重新应用调用者的 Grants。

## 稳定项目身份与授权范围

PROJECT-01 采用显式项目 ID。Server 的项目登记与用户确认的关联是跨设备身份依据；本地目录、规范化路径、Git 地址只作别名，不用它们自动合并业务身份。

- 改名、搬目录、重新克隆不应产生新的逻辑项目身份；新位置必须经关联确认后共享原项目记忆。
- 相同 Git 地址可能对应不同业务项目，不能擅自合并。不同 Git 地址也不能据此否定用户明确登记的同一项目。
- 未登记或关联有歧义时报告需要关联，不偷偷归入另一个项目。离线时无法确认的新关联保持待确认，不按目录名猜测身份。
- Host 的全部项目权限来自已确认的通配 Grant；新项目创建或关联不再次要求逐项目授予，但身份确认、作用域识别和操作权限检查仍须执行。
- Global 是否可访问单独授权；全部项目不包含其它 Host 私有上下文或其它 Session 的任意访问，也不自动包含人工审核、凭据管理等管理权限。
- 有权访问所有项目不意味着每次 Recall 应搜索或注入全部项目，相关性选择由 RECALL-01 另行确认。
