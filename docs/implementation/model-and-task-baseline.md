# 模型与任务：已确认基线及实施缺口

状态：本文件只固化用户全量整理版、ADR-015/016/017/018/019/025/026 已明确的要求。未给出数值或精确算法的项目保持 Open，不把当前代码默认值当作最终规格。

## 已确认的职责

- 工作模型是记忆沉淀的主要决策来源，可以主动提交 Remember/更新候选。
- 后台模型按需辅助质量检查、知识抽象、冲突识别、整理及语义分析，不成为脱离上游编排的独立记忆大脑。
- Gateway 是任务导向的统一模型调用入口，负责配置、选择、参数、超时、错误、结果和使用记录。
- 模型路由按任务类型、能力要求、显式配置及可用性决定；不能散落在 Source、Provider 或业务模块中。
- 调用权限必须 declared 且有授权；Provider 不自行寻找副脑或模型服务。
- 普通 Recall/Remember 的规划优先规则，只有规则不能确定时调用 Planner；可选重排不强制每次调用模型。质量审核仍遵守规则 + LLM 语义检查，不将“无需 Planner”误解为“无需审核”。

## 已确认的失败语义

统一区分暂时性错误、服务不可用、超时、参数/权限错误、模型能力不足。按任务重要程度决定重试、切换、延迟或人工介入；单个模型失败不能令整个系统不可用。

审核无法判断或检查不完整时不得批准；转人工的候选与模型调用失败记录需要保留。模型审核通过或置信度高不等于实际技术验证。

因此，没有模型时仍可运行不依赖模型的既定能力；需要模型的步骤必须明确报告等待、失败或人工介入，不能偷偷跳过必要检查。

## 任务与执行的硬边界

- 持久化队列，首版 Worker 在 Server 模块化单体进程内部。
- Task、Pipeline Run、Execution Receipt 独立身份并关联。
- 业务变更与入队同事务；跨 Provider 不假定共同事务。
- 稳定幂等键、检查点与结果核对；超时不等于外部未执行。
- 暂停、恢复、取消和人工介入是显式状态；服务重启恢复未完成任务。
- 取消、重试和恢复不能覆盖历史、绕过审核或在外部结果未知时盲目重放。

## 第九批已确认的执行预算

所有下列值为可配置默认上限，而非应当用满的调用次数。

- 单次模型调用最多 60 秒。
- 一个模型处理步骤最多 5 分钟，包含等待、退避、主模型重试、备用调用及结果校验；排队等待应单独记录，不能通过反复换 Run 重置已经开始的步骤预算。
- 主模型最多 3 次，含首次；仅对允许重试的暂时性错误继续。配置中的备用模型最多调用 1 次，未配置时不得自行寻找模型。
- 总时限优先于次数；剩余预算不足一次完整调用时缩短调用时限或停止，不能因为还有次数就越过总截止时间。
- 备用模型必须满足同一任务的必要能力、输出契约和授权；缺少必需能力时拒绝，不通过关闭质量检查来构成“降级”。
- 语义不确定、真实冲突或证据不足按审核规则转人工，不反复请求模型直到得到批准。权限/参数/能力错误明确归类，不能作为通用临时错误无意义重试。
- 候选审核最终失败转人工；其他任务根据既定分类进入延迟/失败/人工状态并保留使用记录，基础 Recall 不因此整体停机。

首版后台模型任务最多并发 2 个。模型调用期间不持有长时间 SQLite 写事务；两项任务可以等待各自模型响应，不意味着可并发推进同一逻辑记忆的版本指针或同时重放同一 Provider 写入。

同一任务主模型与备用调用不能以并行竞速方式绕过其次数/并发预算；资源释放、取消、超时和调用结束都需有明确记录。Server 进程内 Worker 是最终部署基线，不能因为原型存在多个启动入口就让每个 Host 各自运行完整后台 Worker。

Provider 结果未知时的核对/前向恢复按外部操作状态机执行，不能套用“主模型 3 次”盲目重写。网络同步等非模型基础设施任务也另有恢复策略，不受该模型调用次数直接支配。

## 第十二批：用量统计（Accepted）

MODEL-06：只记录用量，不额外增加项目级每日/任务 Token 硬配额。每次调用记录任务/步骤/尝试、路由、模型、耗时、结果，以及供应商实际返回的输入/输出/缓存 Token；未返回的字段标为 unknown，估算必须单独标明，不冒充实际值。不记录密钥或完整提示词。重试和备用调用分别计入统计，取消及失败可能仍产生供应商用量。

超时、调用次数、后台并发限制继续有效；模型上下文窗口和供应商限制仍须处理。不可因未配置项目 Token 配额而阻止启动，也不可借只统计用量而取消执行预算。首版无需为此接入付费计费平台；费用仅在有明确价格来源和日期时估算。
