# 模型网关与路由

状态：已确认职责见 ADR-016/017、`model-and-task-baseline.md`；本文记录当前唯一已实现的路由与调用约束，其余策略标为 Planned 或 Open，不冒充已实现。

## 1. 已确认政策

- 所有 MnemoWeave 发起的模型调用统一经过 Gateway；Source、Provider、协议层不得自行寻找模型或携带模型凭据。
- 调用权限必须 declared；只有声明过的组件可以调用模型。
- 工作模型主导记忆沉淀，后台模型按需辅助质量检查、抽象、冲突识别与整理。
- 路由按任务类型、能力要求、显式配置与可用性决定；失败按临时错误、不可用、超时、参数/权限、能力不足分类处理。
- 单次 60 秒、模型步骤 5 分钟、主模型最多 3 次（含首次）、备用最多 1 次、后台并发 2；只记录用量，不设项目级 Token 硬配额。
- 语义不确定、证据不足或真实冲突不得通过反复请求模型变成批准；模型置信度不等于技术验证。

## 2. 当前实现

`ChatModelGateway`（WP3 后）：

| 项 | 事实 |
|---|---|
| 调用方 | 声明组件到能力的映射 `TASK_CAPABILITIES`；当前仅 `candidate-review → semantic-assessment`，未声明组件直接拒绝 |
| 路由表 | 显式路由列表，每条声明 `capabilities`；主路由 `MNEMOWEAVE_MODEL_URL/MODEL/KEY`，备用 `MNEMOWEAVE_BACKUP_MODEL_URL/MODEL/KEY`；两者都必须声明任务所需能力 |
| 端点校验 | 必须 HTTPS，或 `localhost`/`127.0.0.1`/`[::1]` 的 HTTP；URL 不得含用户名密码或查询串；禁止重定向 |
| 协议 | Chat Completions，`response_format: json_object`，要求 `finish_reason=stop` 且无 refusal |
| 超时 | 单次 60 秒（`AbortSignal.timeout`，受剩余步骤预算约束） |
| 步骤预算 | 整个 assess 步骤 5 分钟总上限；耗尽即停止，不再发起重试或备用 |
| 重试 | 临时类失败（temporary/unavailable/timeout）主模型最多 3 次（含首次）、每条备用路由最多 1 次；参数/权限/能力/协议错误立即停止 |
| 失败分类 | HTTP 408/429/5xx→temporary、401/403→permission、404→capability、其它 4xx→parameter、超时→timeout、网络不可达→unavailable、结构或 Schema 失败→protocol |
| 响应上限 | 256,000 字节 |
| 输出校验 | `SemanticAssessment` 严格解析；缺字段或非法结构即失败 |
| 用量记录 | 每次调用写入 `UsageSink`：组件/模型/路由/尝试/结果分类/耗时/排队等待与供应商返回的 Token；缺失字段记 `unknown`，不记零、不估算；凭据不入记录 |
| 用量存储 | 配置状态目录时写入 `<STATE_DIR>/model-usage.jsonl`（独立于 30 天诊断轮转）；无状态目录时输出 stderr `model_usage` 行 |
| 并发 | 信号量限制全局并发模型调用最多 2（TASK-01）；Worker 同时最多并发审核 2 个候选 |
| 失败兜底 | 全部失败向上抛出，由 Worker 转人工；无静默降级 |
| 用户输入 | 候选与相关记忆作为不可信数据处理，提示词显式声明不是指令 |

配置不完整（只有 URL 或只有模型名，主或备用同）在启动时报错；未配置模型时，所有非明显重复候选进入人工审核。

## 3. 与已确认政策的差距

| 政策 | 现状 | 影响 |
|---|---|---|
| 单次 60 秒 | 已实现（WP3） | — |
| 主模型 3 次、备用 1 次 | 已实现（WP3） | 仅 temporary/unavailable/timeout 重试；语义不确定不重试 |
| 步骤总预算 5 分钟 | 已实现（WP3） | 排队等待记录于用量条目；新 Run 不重置步骤预算（预算在 assess 调用内计时） |
| 后台并发 2 | 已实现（WP3） | Gateway 信号量 + Worker 并发审核 2；写入仍全局串行 |
| 用量记录 | 已实现（WP3） | unknown 不记零；存储位置见第 2 节 |
| 路由表 | 已实现（WP3） | 当前仅审核任务一条能力映射；新任务类型扩 `TASK_CAPABILITIES` |
| Rerank（RECALL-02） | 网关层已实现（recall-rerank 能力 + 排列校验）；View 交付默认接线（显式请求或分数歧义触发） | 未配置路由、调用失败或输出非排列时保留确定性顺序并标记 unavailable/failed；Bridge 本地装配不调用模型，标记 unavailable |
| 交互优先/后台防饿死调度（TASK-02） | 已实现（写入先排空；审核随后完成） | 已批准写入在长模型调用前先执行；审核仍并发 2，写入仍由单一全局锁串行化 |

以上剩余差距属于实现缺口，不是新的设计决定；补齐时不得降低“失败转人工”的默认语义。

## 4. 路由与降级规则（Planned）

实现统一路由时至少满足：

- 任务类型 → 必需能力 → 候选路由列表；只有全部满足的模型可被选择。
- 备用模型必须满足同一输出契约与授权；不得通过关闭质量检查构成降级。
- 临时错误才允许重试或切换；参数/权限/能力错误立即停止。
- 每次调用记录：任务/步骤/尝试、路由、模型、耗时、结果、供应商返回的 Token；缺失标 unknown，估算单独标注。
- 超时与次数总上限优先于重试次数；排队等待单独记录，不能用新 Run 重置步骤预算。
- 凭据只在调用边界解析，不进入提示词、日志或回执。

## 5. 审计与隐私

- 不记录完整提示词、候选正文、密钥或模型原始响应。
- 只记录 traceId、任务/候选引用、路由与结果分类。
- 模型响应视为不可信数据；解析失败、截断、拒绝都转人工并保留失败记录。
- 外部模型端点的数据驻留由用户配置决定，不得默认上传到未声明的服务。

## 6. 未决事项

- 工作模型与后台模型如何在同一 Gateway 下分类与限额（MODEL-01/02 的实现细化）。
- 未配置模型时的长期运行策略：是保持“全部人工”，还是提供显式本地规则路径。
- 供应商限流与配额不足的可见性。
- 用量记录的存储位置与保留期（不得混入诊断日志的 30 天轮转）。
