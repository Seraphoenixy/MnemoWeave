# Recall、Pinned 与上下文投影规格

状态：固化 ADR-013/014/024 及 RECALL-01、VIEW-01、VIEW-02 的明确选择。检索权重、重排阈值、摘要生成策略和具体工具字段在契约文档中细化，不把原型实现当作这些参数的最终答案。

## 默认检索范围

默认搜索调用 Host 已授权的全部项目，以及单独获准的 Global 记忆。该行为是用户的明确选择，不限于当前项目。请求可显式缩小范围；不能借扩大检索参数超出 Grants。

跨项目结果必须保留项目身份、来源、版本、平台/环境/前置条件及限制。检索到其它项目的实践不代表已验证适用于当前任务，更不自动复制或晋升 Global；跨项目抽象另行生成候选并审核。

Host、Session 私有内容仍按各自授权控制，全部项目授权不隐含读取其它 Host/Session 的私有运行上下文。项目 ID 必须来自已确认登记，不能用当前路径名字猜测项目身份。

## 检索与版本语义

先验证本地身份、读取许可和作用域，再执行允许范围内的 Local-first 检索。许可过期、撤权、损坏或无法证明可用的本地数据不参与结果；不能通过历史查询、缓存或旧 View 绕过。

先应用发布/版本/状态与适用条件过滤，再进行多路召回、合并、去重、实体关系扩展和可选重排。原生 Provider 的 superseded 是检索信号，不是 MnemoWeave 当前指针或业务作用域的替代物。

默认有效查询不把暂存版本当成已发布，也不把被替代或 Invalidated 内容当当前确定结论。显式历史请求允许在授权范围查询不可变历史，并标出其时间、状态和适用条件；历史记录存在不意味着当前有效。ReviewDue 只表示需要复核，不得等同删除或自动 Invalidated。

本地缺失、检索被截断、历史未同步齐或副本重建时，结果需标明数据时间与完备性；联网可补充 Server。不能以“0 条命中”假装已完成一个实际上被截断或无权执行的查询。

## Pinned 分级

- 明确标为关键的约束应完整呈现，不得静默截断、压缩或被低价值内容挤掉。
- 普通 Pinned 可采用可追溯摘要，保留 Memory/Revision 身份、来源及获取原文的入口。摘要是展示派生物，不是新正式记忆或原内容修改。
- 剩余预算用于与任务相关的动态内容。Pinned、Dynamic Projection 以及查询权限各有职责，不能因已固定就绕过权限或版本检查。
- 关键约束本身超出允许预算时，返回明确的预算异常/需要调整状态，不将残缺 View 冒充成功。是否经用户调整范围、预算或分阶段获取必须可见。

Pinned 支持 Global/Project/Host/Session；它们是作用域而非未经确认的固定排序。本规格不暗中假定 Session 必然覆盖 Global，也不把某一来源的旧约束覆盖另一来源的已确认架构决策。

## 注入预算

Host 未报告可用预算时，所有注入内容合计默认上限为 **4,096 Token**，可配置；包含关键/普通 Pinned、动态段落、来源/版本说明及投影封装元数据，不是每个部分分别 4,096。

Host 报告更小预算时遵守更小值；适配器还需尊重 Host 的实际注入能力与限制。Host 未暴露完整窗口时，不能承诺该兜底值证明其整个上下文不会溢出。

计数方式应记录使用的 tokenizer/估算方法及安全余量。无法精确计数时使用保守估算并标明，不能把字数或字符数直接声称为精确 Token。需要额外信息时用主动 Recall 分阶段获取。

## View 与动态更新

View 为结构化且不可变的本轮执行上下文，包含记忆、来源、作用域、适用条件、授权绑定、优先级、预算和版本元数据。基线 Projection 与动态增量可复用计算，但交付后不原地改写 View；变化生成新 View/版本。

旧 View 的存在不延长读取许可。对已经送给 Host 的上下文无法强制“收回”，但后续读取、再次注入、操作和换用新 View 仍须检查实时已知撤权及许可有效性。

行为评估记录是否注入、模型是否使用/遵循和反馈证据；不把“已发送提示词”当作已遵循，不把模型自评当作实际技术验证。反馈形成候选改进或治理任务，不直接覆盖正式知识。

## 第十二批：按需模型重排（Accepted）

RECALL-02：普通查询使用确定性排序。用户明确请求重排，或规则判定候选歧义较大时，才经 Model Gateway 发起可选重排；未配置/失败必须标记为未重排。不得通过重排扩大权限、读取过期副本、恢复已过滤的暂存版本或将模型分数当成事实正确性。

工程契约建议（Proposed）：输出 rerank.status（not_requested / applied / unavailable / failed）、reason 和实际路由；自动触发还记录规则版本和触发依据。具体歧义阈值作为可配置、可测的排序参数，不冒称用户已选择某一分差。

重排输入先执行权限和正式目录过滤，仅包含必要候选信息；输出只能重排输入集合，必须校验未知 ID、重复 ID、遗漏及非法结构。失败保留确定性结果并附状态，不能伪称执行成功。若调用方把重排声明为必需 Capability，则明确返回能力/执行失败，不把未重排结果作为满足条件的成功响应。整个过程仍服从模型步骤时间、重试及并发预算。
