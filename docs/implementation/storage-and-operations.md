# 存储预算、日志与同步保留规格

依据：ADR-020/023/026，STORAGE-01/02、OPS-01、SYNC-06 和既定生命周期选择。本文仅定义 MnemoWeave 管理的数据，不授权清理用户其它目录或更改 Mnemon 内部表。

## 首装预算

Server 和 Bridge 各自设置软、硬预算。安装/配置流程读取实际数据分区可用情况给出建议，由用户明确确认；不将曾讨论的固定 20 GiB/10 GiB 值当默认。

未配置预算时仍提供诊断和设置入口，暂不启动非关键采集。不能假称全部业务 ready，也不能一边等待配置一边无限接收大内容。正式配置的校验、就绪状态和写入拒绝理由应可观察。

达到软限制触发容量提示、清理计划及已有治理机制；达到硬限制限制非关键增长。清理只能处理已满足保留/引用条件的数据，不以磁盘紧张为由静默删正式历史、受保护证据或未完成意图。

配额与实际磁盘不足分别检测：配额仍有余量不代表文件系统有空间；磁盘不足也不能导致部分写入被误报为持久化成功。事务失败、Blob 暂存失败、队列满和预算未配置必须有明确错误语义。

本地 SQLite 不额外加密，操作系统用户级权限必需，磁盘加密由用户自管。模型/Bridge/Host 凭据仍需专门的凭据配置与权限保护，不因数据库不加密而允许写进普通诊断日志。

## 诊断日志

默认保留 30 天，按来源时间及轮转策略管理，不因读取日志重置保留期。日志记录结构化错误分类、Trace ID、任务/执行引用、组件、时间和必要运行统计；不默认写记忆正文、完整提示词、原始工具大输出或密钥。

模型使用记录和审计证据与诊断日志区分。审核决定、正式 Receipt、不可变版本关系及必要证据不能随 30 天日志轮转消失。需要临时调试采样时应有显式配置、范围和期限，不能悄悄启用全文记录。

告警至少覆盖配额/磁盘、Provider 完整性、队列积压、持续基础设施故障超过 24 小时、同步许可/游标和迁移失败。健康与就绪分开，单个可选模型不可用不等于整个服务死亡。

## 增量流与删除/移除标记

增量日志默认 30 天；删除/移除标记默认 90 天。它们服务于增量恢复和防止旧副本复活，与正式历史保留、候选正文 30 天、Session 7+90 天及诊断日志 30 天分别管理。

Server 必须知道最早仍受支持的 Cursor；日志压缩后旧 Cursor 明确失效，Bridge 转入一致性快照重建，不能把 Cursor 跳到最新位置并假称同步完成。标记压缩后同样不能允许过旧副本重新上传或复活被移除记录。

区分数据生命周期移除与访问撤权：撤权后按 AUTH-02 保留本地副本但禁止访问，不将通用 Tombstone 应用逻辑简单写成无条件删除所有本地正文。业务删除、当前版本切换、归档、Superseded 和撤权应有可区分的事件语义。

增量与权限状态可影响检索可见性，但不把“停止在某个作用域显示”当作可以物理删除远端历史。旧意图重连后仍需 Server 验权和业务基线检查，不能利用旧 Cursor 或保留标记绕过。

## 安全清理与恢复

大内容采用内容寻址 Blob，元数据记录引用与哈希；仅无活动引用且达到保留条件的对象可回收。暂存副本、重建中间数据、升级快照和离线队列分别登记，不能用遍历目录按文件年龄删除替代引用管理。

升级前备份、版本化 Migration、失败停止业务及优先向前修复沿用 ADR-026。预算限制不能悄悄跳过备份；空间不够应拒绝升级并给出诊断。副本重建保留队列，许可过期不会因重建成功自动续期。
