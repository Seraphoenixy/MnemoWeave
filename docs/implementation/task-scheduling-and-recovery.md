# 任务状态、调度与恢复规格

依据：ADR-018/019/025/026、TASK-01 至 TASK-04 和模型预算。Server 进程内持久化 Worker 是首版形态，不要求引入独立队列服务或 Docker。

## 实体与边界

Task 是业务意图及其生命周期，Pipeline Run 是一次具体执行，Execution Receipt 是外部步骤的结果凭据。三者分别具有稳定身份并关联，不能合并成一个会被反复覆盖的成功/失败字段。

业务状态变更、Task、Outbox 入队必须在同一数据库事务中提交。模型和 Provider 调用不占用长时间数据库事务；外部结果经核对后以短事务保存检查点和回执。没有跨 Provider 共同事务假设。

稳定业务意图、不可变计划、目标版本基线、外部步骤幂等键与 Run 的关系必须保留。新 Run 不得擅自换基线、换写入键、抹掉旧失败或重置已消耗的模型步骤预算。

## 状态职责

实现必须分别表达：等待执行、执行中、等待基础设施恢复、暂停请求/已暂停、取消请求/已取消、等待人工、成功和终止失败。具体字段枚举由统一契约固化，不用 Candidate 的 Approved/Persisted 代替 Task 控制状态。

批准只表示允许按计划推进，不是 Provider 已成功；收到网络响应、提交本地队列、Server 接收、审核通过和正式持久化属于不同确认层级。

## 调度

交互触发的审核/可靠写入优先于普通批量整理，同时必须给长时间等待的后台任务执行机会。撤权、凭据失效等即时安全控制不能被普通工作队列阻塞。

优先级不能越过依赖、严格 Grants、写入串行保护或业务占用。后台模型任务同时最多 2 个；无模型本地 Recall 不占用这两个槽位。任务等待和模型预算应分别观测。

公平性通过可测试的调度规则固化，至少能证明持续交互负载下后台任务不会永久饿死；不能仅声称“有优先级”。具体权重/老化阈值在最终配置表注明，不能凭当前原型默认值当作已确认值。

## 租约与接管

Worker 执行租约默认 90 秒，每 30 秒续期。健康 Worker 可以不断续期，所以一个任务允许超过 90 秒；模型步骤仍另受 5 分钟总上限约束。

领取、续期、检查点和最终提交必须携带执行者/代际标识并执行 fencing。过期 Worker 即使后来恢复，也不能提交新状态或覆盖接管者结果。租约过期只表示可进入接管核对，不能证明旧外部调用从未执行。

逻辑记忆的持久化业务占用与 Worker 租约分开：租约失效不自动释放正在恢复的版本操作基线，也不允许另一更新绕过 expectedCurrentRevision。

## 重试分类

| 分类 | 必须行为 |
|---|---|
| 模型临时故障 | 60 秒单次、5 分钟步骤、主模型最多 3 次/备用最多 1 次；语义不确定转人工 |
| 非模型可恢复基础设施故障 | 持久化退避重试，间隔最多 15 分钟；超过 24 小时告警，保留待恢复，不自动放弃 |
| 权限/能力/参数问题 | 明确归类并停止错误路径，等待修正；不能反复重试争取越权 |
| 目标基线冲突 | 停止当前发布计划，保留原意图及证据，要求重新判断，不自动重基线 |
| Provider 写入结果未知 | 先查 Receipt、检查点和官方结果；没有明确结果不能按普通网络重试重发写入 |
| Provider 完整性异常 | 停止自动推进并保留审查材料，不用候选正文伪造正式读取成功 |

“15 分钟”是单次重试等待间隔的上限，不是仅恢复 15 分钟；“24 小时告警”不是自动取消或删除期限。进程重启保留故障开始时间和重试计划，不能反复重启重置告警计时。重连/资源恢复可触发重新评估，但仍需预算和权限检查。

退避需防止大量任务同时重试；服务返回的合理重试提示应纳入调度，总上限与紧急控制不能失效。所有可调整参数在配置表集中声明。

## 暂停、取消与恢复

暂停/取消先保存请求状态，由执行机制在安全检查点处理。不能把持久化一个标志误报为已经停止外部调用；实际中断能力和结果是否未知必须可见。

尚未执行不可逆外部步骤时可以按计划取消并保存记录；已经产生不可逆关系投影等副作用时优先核对和前向恢复，不能通过物理删除历史或伪造回滚完成取消。

人工恢复必须明确目标和理由；确认旧执行者停止不等于宣称外部未提交。恢复仍复用稳定意图/步骤身份，核对外部结果后从最近有效检查点继续。

## 验收要求

覆盖重启、Worker 超时后复活、重复领取、重复消息、模型慢调用、长期断网、后台公平性、暂停/取消竞争、外部提交后响应丢失、审核/Outbox 同事务故障以及不可逆步骤后的恢复。证据同时包含治理状态和真实 Provider 行为，不能只用 mock 返回成功证明跨系统可靠性。
