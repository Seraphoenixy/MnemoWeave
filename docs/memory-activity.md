# 记忆活动记录与同步

记忆活动用于评估系统的读、写和委派效果。用回合与子任务关联键可以追踪一次召回是否返回候选、子 Agent 是否完成、以及写入是否收到持久提交回执。统计时区分没有命中、预算跳过、执行失败和结果未知。召回结果表示工具返回的证据，模型实际是否采用仍未知。

## 采集边界

| 事件 | 来源 | 记录 |
|---|---|---|
| 召回、关联遍历和档案检索 | DSH 会话中配对的命名记忆工具调用和结果，MCP 的工作准则读取 | 来源、操作、结果条数、有限的条目引用、是否重放既有证据、跳过原因、结果状态 |
| 写入 | DSH 工具结果及其提交回执，MCP 的本机写入结果 | 操作、记录引用及已提交、跳过、未确认或失败状态 |
| 子 Agent | MnemoWeave 委派协调器的实际运行结果 | 父会话、回合、子会话、任务类型、终态、耗时、可取得的 token 用量 |

工作区使用自身的活动目录。即使 DSH 共用一个记忆数据根，不同工作区也按工作区标识分开。MCP 的工作准则读写归入单独的全局活动流。新记录随操作产生，无需重扫历史会话。DSH 接续的子会话仅采集本次会话实际执行的回合。

DSH 在回合结束后保存工具活动，委派协调器在运行收尾时保存子任务活动。缺少终态、时间或用量时会标为未知或省略对应字段。工作台直接预览、后台 Provider 内部操作及完整子会话仍使用各自的记录。被排除的工作区不采集 DSH 活动。

## 本地存储

活动记录为版本化 JSON，按事件 ID 各存一份，原子发布后视为不可变。DSH 工具事件的 ID 从会话与调用身份确定，重复接收同一回合可去重。MCP 调用和委派运行使用独立运行 ID。会话及条目引用只保存稳定摘要，记录不含正文、查询词、路径、提示词、工具参数、原始错误、工具输出或凭据。记录失败会报告固定错误，记忆操作仍以自己的工具回执为准。

工作区文件位于当前数据根的 `state/activity/workspaces/<workspace-id>/events/`。MCP 全局活动位于 `working-rules/state/activity/events/`。可以直接读取这些 JSON 文件做离线分析。活动目录与记忆 Pack 独立，导入或替换 Pack 不会改动活动。

## 同步

DSH 的 **记忆系统 → 设置 → 存储 → 服务器同步 → 同步全部** 会同步已登记且未排除的工作区活动，以及全局工作准则活动。MCP 配置同步服务后，在工具读写时尝试同步全局工作准则活动。活动通过 PAKE 会话和变更批次接口追加，使用独立于记忆快照的 scope。

客户端下载并验证活动批次，先合并不可变事件，再保存游标。上传仅提交在本机产生且当前目标尚未确认的事件，以事件 ID 为记录键。更改同步目标时，从旧目标拉取的事件仍留在本地历史中。发生游标冲突时，先拉取新提交，再计算仍需上传的条目。重试、进程重启和两台机器分别追加都保留已上传的活动。缺少回执的上传会通过重放远端日志确认。服务端在写入批次的同一事务里登记事件 ID，并拒绝覆盖和删除。

升级需要部署支持活动事件校验的同步服务，并更新发起同步的 DSH 或 MCP。现有记忆同步范围、快照格式和游标可继续使用。

每批最多 128 条上传记录。活动流累计历史，当前版本没有自动删除，也不从原始 DSH 会话回填。远端可读取已同步的结构化记录。同一服务器上的 DSH 工作区名称仅在同步同一个工作区时复用。
