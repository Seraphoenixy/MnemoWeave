# 当前状态

## 实现状况

工作区模型、同步协议 2 与准则全文注入已实现并纳入自动验证；真实宿主、部署与其他未决边界见下方「待完成或待验收」。目标边界见 [架构](architecture.md)，实施契约见 [实现与契约](implementation.md)，协议见 [同步协议](sync.md)，切换步骤见 [旧版同步切换](#旧版同步切换)。

| 目标 | 当前实现 |
|---|---|
| 正式记忆共享 | 单一共享集合。目录、列表、图谱和召回均无条目级工作区字段与同步流字段；出现已移除字段返回 `INVALID_INPUT`。查重跨整个集合。工作区名称只作为召回线索进入查询文本 |
| 工作区档案 | 按稳定 `workspaceId` 跨会话共享，设备各自绑定本地根目录，会话绑定不可中途更换。管理列表、搜索和新增必须选择工作区，缺少时返回 `WORKSPACE_REQUIRED`。旧档案经 v22 迁移保留原 ID、版本与历史 |
| 同步流 | 协议 2 使用 `rules`、`formal-memories` 与 `workspace-archives:<workspaceId>`。写入流由条目类型和 `payload.workspaceId` 派生，客户端不能指定。设备授权、序号、游标、快照按流隔离。远端 v2→v3 迁移把旧 `global` 授权复制为两条流授权，旧 `project:*` 授权及旧档案按明确的工作区对照表重建，缺少映射或合并授权不一致时停止迁移。旧日志与游标退出运行状态，迁移流首次读取快照 |
| 准则与注入 | 聚合 View、`/v1/view`、`memory_view` 与 `runtime_context` 已移除。`/v1/inject` 只返回完整准则集合；10,000 UTF-8 字节容量按所有未移除准则计量（含停用条目），超限写入拒绝且不自动归档，只允许使集合变小的替换和移除；入站超限集合进入 `needs_review` 而不推进游标 |
| 条目版本 | 正式记忆提交 `entryVersion`，准则与工作区档案提交 `baseVersion`；服务端不补全为本机最新版本，过期基准返回 `VERSION_CONFLICT` |
| 写入任务 Agent | `/v1/memory-write-tasks/{taskId}/actions/{index}` 按 (Host, 任务, 动作序号) 幂等，先写 `unknown` 再结算；同键异载荷返回 `IDEMPOTENCY_CONFLICT`。Server 在占用幂等键前校验触发方式、动作白名单、每任务动作数、证据引用可解析和目标运行状态，超出返回 `SCOPE_FORBIDDEN`/`INVALID_INPUT`，被拒绝的动作不留下回执；草稿提炼同时禁止显式正文与分类。回执状态见 [实现与契约](implementation.md#授权任务接口)。界面与人工审批仍走各自入口 |
| 主动记录工程经验 | DSH 原生工具与通用 MCP 共用同一份经验指引。无委派能力时 `mnemoweave_remember` 返回候选回执，不报告发布 |
| 准则、档案与正式记忆工具 | `mnemoweave_read_rules`、`mnemoweave_workspace_archives`、`mnemoweave_related` 已注册；档案搜索与分段读取共用每轮四次额度、单次 6,000 字符 |
| DSH 会话与轮次 | 工具从执行上下文取 Host、会话、Agent 和轮次，模型参数不能提供。每轮预算在 Source 调用前校验；部分身份被拒绝为 `UNAUTHORIZED`，不退到管理额度。`/no-retention` 命令把本轮标记经宿主事件报给 Server，`remember`、准则和档案写入在该轮被拒绝；标记只覆盖该轮 |
| 空闲复盘 | 仅在有模型路由和证据时启动；连续空闲 30 秒、活动分达到 5、两次尝试间隔 5 分钟、最多 20 次。扫描读取本机保留的用户轮次（含不留存标记）；动作经授权任务接口提交，Server 校验运行属于发起 Host、同会话且仍在运行。每次至多一条准则变更及一篇新建档案，不写正式记忆。失败运行只重试未完成动作 |
| 档案容量与状态 | 单篇 2 MiB、每工作区活跃 10 MiB，按 UTF-8 字节；归档不占活跃容量并保留历史。同步开启时由远端确认容量与状态 |
| 档案提炼 | 档案详情提供「提炼为正式记忆」：`POST /v1/archive-distillations` 固定来源版本与哈希，草稿按 Host 读取并可修改或放弃；确认后经写入任务发布，来源在预览后变化返回 `VERSION_CONFLICT`，重放返回原回执。原档案版本与状态不变，同步记录不暴露来源元数据 |
| 快照可见性 | 远端在单个事务内建立快照；本机逐条核对并暂存投影，全部成功后在同一事务内写入投影并推进游标 |
| 请求体容量 | 本机与同步 HTTP 单次 JSON 上限 16 MiB |
| 界面术语 | 六个页签为「概览」「准则」「工作区档案」「正式记忆」「技能」「设置」；概览卡、准则页、档案页与同步页统一使用同一套名称，旧「运行时记忆」「项目档案」不再出现。管理页无归属字段和工作区筛选，档案页选择已登记工作区，同步页按同步流显示协议 2 状态 |
| 工作上下文边界 | 本机不保存会话投影，也不提供工作上下文读写入口。只记录操作所需的会话绑定、事件标识、任务证据，以及作为复盘与写入证据的用户轮次原文；助手输出、工具输出和附件留在宿主。用户轮次正文和轮次标记按 7 天到期清理 |

### 接口与界面迁移

| 已迁移 | 契约 |
|---|---|
| `GET /v1/workspaces`、`POST /v1/workspaces`、`PUT /v1/workspaces/{workspaceId}/binding`、`PUT /v1/sessions/{sessionId}/workspace` | 工作区登记、目录绑定与会话绑定。会话绑定不可中途更换，管理页选择不影响任何会话绑定 |
| `GET/POST /v1/archives`、`PATCH /v1/archives/{entryId}`、`POST /v1/archives/{entryId}/state`、`GET /v1/archives/search`、`GET /v1/archives/{entryId}/content` | 档案路由族使用 `workspaceId`；列表、搜索和新增缺少工作区时拒绝 |
| `GET /v1/sync/streams`、`?stream=` | 协议 2；缺少或不满意的协议头返回 HTTP 409 `SYNC_PROTOCOL_MISMATCH` |
| 宿主配置 `MNEMOWEAVE_WORKSPACE_ID` | 旧 `MNEMOWEAVE_PROJECT_ID` 只记录 `config_expired`；`x-mnemoweave-project` 不再读取 |

## 旧版同步切换

本机 v21→v22 和远端 v2→v3 迁移读取同一份 `MNEMOWEAVE_LEGACY_WORKSPACE_MAP` JSON 文件。协议 2 握手、远端映射及按流快照有自动验证。真实数据切换须先在隔离副本走完以下步骤并核对清单。若副本已经过早期的部分迁移，从 v21/v2 原始备份重新演练。目标协议握手见 [远端 HTTP](sync.md#远端-http)。

1. 停止所有宿主写入，保持同步循环运行，等待各设备的 Outbox、Inbox 和共享发布队列排空。存在未确认、冲突、无法核对、仅本机已发布但未共享的记录，或设备无法参与时停止切换。遗留候选与审核状态保留。
2. 停止全部旧版本地和远端 Server。分别备份各治理库、Mnemon Store 和远端同步库。以远端当前态及修订为输入，清点条目逻辑 ID、条目版本、哈希、关系及撤回状态。在隔离副本验证以下步骤后才执行真实切换。
3. 生成并备份迁移对照表。每个旧 `projectId` 必须明确映射到一个新工作区 UUID 和显示名称。档案或设备授权缺少映射时停止切换。多个旧项目映射到同一工作区时，旧授权必须完全相同（包括缺少授权），否则停止切换，由执行者先调整授权或改用不同工作区。不得通过合并自动扩大访问权限。旧授权若为仅写，停止切换，由执行者明确改为读写或撤销。其余旧授权保持原权限等级。旧 `global` 的授权分别复制到 `rules` 和 `formal-memories`。旧 `project:<projectId>` 的授权通过迁移对照表复制到对应的 `workspace-archives:<workspaceId>`。只持有旧项目授权的设备不会因此取得正式记忆权限。旧项目范围的正式记忆将向拥有 `formal-memories` 读权限的设备可见。执行者必须确认该对照表和数据可见性变化后再迁移。文件以旧项目 ID 为键，例如 `{"alpha":{"workspaceId":"11111111-1111-4111-8111-111111111111","name":"Alpha"}}`。
4. 在远端单个事务内，按条目类型重建条目索引与设备授权。协议 1 的 `runtime` 转为 `rule`，`formal` 转为 `formal-memory`，`archive` 转为 `workspace-archive`。旧档案通过迁移对照表将旧 `projectId` 转为 `payload.workspaceId`。正式记忆统一进入 `formal-memories`，保持逻辑 ID、条目版本、正文、哈希、关系和撤回状态。准则和工作区档案也保留原 ID、版本和业务数据。新同步流从序号 0 开始，旧日志和回执留在备份。禁止将旧游标或未完成请求带入新协议。
5. 保持宿主停写，在隔离状态目录启动每台本机 Server，清除旧同步游标和已完成的同步队列缓存，按新授权重新读取每个同步流快照。优先按原逻辑 ID、修订版本和正文哈希复用本机 Provider 映射，缺失正文通过官方 Provider 重建。已完成的宿主任务回执、候选、准则本机归档保留。旧工作上下文投影留在迁移备份，不导入目标运行状态。移除正式记忆目录中的旧归属字段，按对照表登记工作区。旧项目配置不自动绑定本机路径，管理员在新协议启用后显式绑定本地根目录。同步投影从新快照重建，工作区档案快照不得退休正式记忆；迁移将旧同步正式记忆目录投影暂时隐藏，仅在完成有授权的正式记忆流快照后解除该快照所包含条目的限制。开放宿主访问前核对无读授权设备的目录。所有快照应用完成，数据和授权与清单一致后才开放写入。
6. 失败时保持停写。开放写入前可成套恢复远端库、各治理库和 Mnemon Store；开放写入后不得直接回滚到切换前备份。纯本机模式只需迁移本机治理库，使用同样的对照表迁移档案，移除正式记忆归属字段，保留逻辑 ID、版本、修订、哈希和 Provider 映射。

迁移旧载荷时，准则缺失的 `importance` 和 `pinned` 分别填为 `normal` 和 `false`。档案缺失的 `state` 和 `archivedAt` 分别填为 `active` 和 `null`。已有重复正式记忆保留原逻辑 ID。本机 schema 从 v21 升为 v22，远端从 v2 升为 v3。v17 引入的正式记忆旧归属列为 `project_id`，与新工作区 ID 无关。

## 当前已实现

当前本机治理库 schema v23。

- 本机 HTTP 与 stdio MCP、候选审核、Worker 可靠写入、正式记忆目录、版本与冲突治理。
- 准则、工作区档案和正式记忆均已有浏览与写入入口。正式记忆支持撤回和历史读取。准则按 UTF-8 字节维护容量，超限拒绝且不自动归档。工作区档案已有归档、恢复、版本历史、容量控制和按工作区的目录绑定。
- 空闲复盘信号筛选：DSH 在每轮结束时请求一次扫描；Server 按已完成的用户轮次、纠正/常驻指令/可留存事实规则选出信号，跳过短文本、提问、非用户消息、重复文本和标记不留存的轮次；水位与信号按 Host 会话持久化，达到上限的轮次下次重试。启动门槛（空闲、活动分、冷却、尝试上限）与「不留存」拦截已实现。
- 召回与嵌入诊断：`GET /v1/diagnostics/embeddings` 转述 Mnemon 官方 `embed --status` 报告（服务与模型可用性、覆盖条数、覆盖率），推导语义/关键词召回模式并报告降级原因；设置页展示召回模式、覆盖、嵌入后端与最近错误。`POST /v1/diagnostics/embeddings/backfill` 启动一次持久化的 `embed --all` 任务，同一类任务单飞，重启后遗留任务标记为 interrupted。
- 远端同步服务、设备授权、版本确认、Outbox/Inbox、断网恢复和协议 2 的按同步流快照重建。
- DSH 会话注入、模型工具、记忆编辑、用户触发的整理后保存，以及技能页中的会话复盘、草案和文本回测。DSH 按持久化轮次固定准则块，同一轮后续模型步骤复用；准则变化在下一轮生效。
- Windows 本机 Server 发布、计划任务注册与唤醒。Linux 远端部署单元已提供。
