### 评审问题待办

下列待办记录当前实现的已知差距。设计和通过条件分别在对应的目标文档中定义。

- [ ] **工作区档案工具越界**。当前工具优先使用模型传入的项目 ID，本机客户端授权也使用项目通配。按 Host 与会话绑定在 Server 操作边界校验目标档案。管理页工作区选择与会话工具分别验证。
- [ ] **正式记忆筛选和查重不一致**。当前查重可以返回另一个项目的条目而不满足旧目标范围，图谱和列表处理 `includeGlobal=false` 的方式也不同。按目标移除项目归属筛选，统一全库查重和回执。
- [ ] **分类跨本机、Provider 和同步漂移**。当前 Provider 写入未传分类等字段，同步创建和编辑使用固定值。核对分类、重要度、标签、实体在新增、编辑、快照恢复和本机 Provider 之间的投影。
- [ ] **无同步编辑缺少正文回读与可靠恢复**。本机编辑在核对 `replaced_id`、正文哈希和关系之前不能推进目录；Provider 已写而目录未提交时须从稳定操作标记恢复。
- [ ] **整理及空闲复盘目标校验**。现有实现以召回命中和版本为主要写入条件。切换到共享集合后仍须绑定触发来源、证据、任务实际读过的目标和允许动作。禁止模型借整理自动撤回未由用户点名的目标。
- [ ] **本机发布早于同步确认**。分别报告本机候选、排队、结果未知及远端确认后已应用的发布结果；补齐同一任务重放和复盘失败信号重试。
- [ ] **原生撤回与正式记忆撤回语义**。治理目录撤回保留历史，直接操作同一个 Mnemon Store 仍可能读取原生记录。验收产品召回、图谱和注入均排除撤回记录，历史仍可读。
- [ ] **召回与嵌入诊断**。全 Store 排序后过滤旧修订与未登记记录可能吃掉结果窗口；覆盖率推导的召回模式无法反映单次查询的原生降级。补足窗口和诊断验收。
- [ ] **上游流程能力差距**。回复旁保存、子 Agent 继承会话授权与独立预算、整理任务历史、既有准则归档的迁移与只读处理均待落实。上游的多 Provider 空间、自动迁移到原生记忆、Git Pack 和原生淘汰是架构差异，按本项目目标验收。
- [ ] **桌面宿主配置与准则提示**。核对打包的 MCP 子进程获得本机 URL、服务令牌和 Host ID。验证整组准则交付与超限失败提示，并实测三个宿主的截止、注入和工具发现。
- [ ] **保留与关系**。原生自动淘汰关闭，旧修订和撤回正文继续占用 Store。确定历史保留和配额默认值；验证同步后的 `supersedes`，其他原生关系扩展仍待实现。
- [ ] **修复三项已知 E2E 断言或输入**。DSH 用例查询旧正文，发布同步用例的断言文字与提交内容不一致，ZCode 运行时用例的 pin 请求缺少现有契约的 `scope`。修复后用真实 Mnemon 重跑。
- [ ] **更新现有恢复演练与文档契约测试**。`tests/e2e/restore-drill.test.ts` 当前验证旧归属字段，目标改验工作区档案与共享正式记忆。更新 `docs-consistency.test.ts` 的旧页签和本机 schema v21 基线。

## 旧版同步切换

- [ ] 在隔离副本完成以下切换和回滚演练，再执行真实切换。目标协议握手见 [远端 HTTP](sync.md#远端-http)。

1. 停止所有宿主写入，保持同步循环运行，等待各设备的 Outbox、Inbox 和共享发布队列排空。存在未确认、冲突、无法核对、仅本机已发布但未共享的记录，或设备无法参与时停止切换。遗留候选与审核状态保留。
2. 停止全部旧版本地和远端 Server。分别备份各治理库、Mnemon Store 和远端同步库。以远端当前态及修订为输入，清点条目逻辑 ID、条目版本、哈希、关系及撤回状态。在隔离副本验证以下步骤后才执行真实切换。
3. 生成并备份迁移对照表。每个旧 `projectId` 必须明确映射到一个新工作区 UUID 和显示名称。档案或设备授权缺少映射时停止切换。多个旧项目映射到同一工作区时，旧授权必须完全相同（包括缺少授权），否则停止切换，由执行者先调整授权或改用不同工作区。不得通过合并自动扩大访问权限。旧授权若为仅写，停止切换，由执行者明确改为读写或撤销。其余旧授权保持原权限等级。旧 `global` 的授权分别复制到 `rules` 和 `formal-memories`。旧 `project:<projectId>` 的授权通过迁移对照表复制到对应的 `workspace-archives:<workspaceId>`。只持有旧项目授权的设备不会因此取得正式记忆权限。旧项目范围的正式记忆将向拥有 `formal-memories` 读权限的设备可见。执行者必须确认该对照表和数据可见性变化后再迁移。
4. 在远端单个事务内，按条目类型重建条目索引与设备授权。协议 1 的 `runtime` 转为 `rule`，`formal` 转为 `formal-memory`，`archive` 转为 `workspace-archive`。旧档案通过迁移对照表将旧 `projectId` 转为 `payload.workspaceId`。正式记忆统一进入 `formal-memories`，保持逻辑 ID、条目版本、正文、哈希、关系和撤回状态。准则和工作区档案也保留原 ID、版本和业务数据。新同步流从序号 0 开始，旧日志和回执留在备份。禁止将旧游标或未完成请求带入新协议。
5. 每台本机 Server 进入迁移模式，清除旧同步游标和已完成的同步队列缓存，按新授权重新读取每个同步流快照。优先按原逻辑 ID、修订版本和正文哈希复用本机 Provider 映射，缺失正文通过官方 Provider 重建。已完成的宿主任务回执、候选、准则本机归档保留。旧工作上下文投影留在迁移备份，不导入目标运行状态。移除正式记忆目录中的旧归属字段，按对照表登记工作区。旧项目配置不自动绑定本机路径，管理员在新协议启用后显式绑定本地根目录。同步投影从新快照重建，工作区档案快照不得退休正式记忆；没有 `formal-memories` 读权限的设备不可保留旧同步正式记忆的可读目录投影。所有快照应用完成，数据和授权与清单一致后才开放写入。
6. 失败时保持停写。开放写入前可成套恢复远端库、各治理库和 Mnemon Store；开放写入后不得直接回滚到切换前备份。纯本机模式只需迁移本机治理库，使用同样的对照表迁移档案，移除正式记忆归属字段，保留逻辑 ID、版本、修订、哈希和 Provider 映射。

迁移旧载荷时，缺失的 `importance`、`pinned`、`state`、`archivedAt` 分别填为 `normal`、`false`、`active`、`null`。已有重复正式记忆保留原逻辑 ID。本机 schema 从 v21 升为 v22，远端从 v2 升为 v3。v17 引入的正式记忆旧归属列为 `project_id`，与新工作区 ID 无关。

## 当前已实现

当前本机治理库 schema v21。

- 本机 HTTP 与 stdio MCP、候选审核、Worker 可靠写入、正式记忆目录、版本与冲突治理。
- 准则、旧项目档案和正式记忆均已有浏览与写入入口。正式记忆支持撤回和历史读取。准则按 UTF-8 字节维护容量。旧项目档案已有归档、恢复和版本历史，工作区 ID 与本地目录绑定属于目标契约。
- 空闲复盘信号筛选：DSH 在每轮结束时请求一次扫描；Server 按已完成的用户轮次、纠正/常驻指令/可留存事实规则选出信号，跳过短文本、提问、非用户消息和重复文本；水位与信号按 Host 会话持久化，达到上限的轮次下次重试。DSH 已接入新增与明确纠正的写入任务 Agent。
- 召回与嵌入诊断：`GET /v1/diagnostics/embeddings` 转述 Mnemon 官方 `embed --status` 报告（服务与模型可用性、覆盖条数、覆盖率），推导语义/关键词召回模式并报告降级原因；设置页展示召回模式、覆盖、嵌入后端与最近错误。`POST /v1/diagnostics/embeddings/backfill` 启动一次持久化的 `embed --all` 任务，同一类任务单飞，重启后遗留任务标记为 interrupted。
- 远端同步服务、设备授权、版本确认、Outbox/Inbox、断网恢复和协议 1 的按范围快照重建。
- DSH 会话注入、模型工具、记忆编辑、用户触发的整理后保存，以及技能页中的会话复盘、草案和文本回测。DSH 按持久化轮次固定 View，同一轮后续模型步骤复用；准则和来源变化在下一轮生效。
- Windows 本机 Server 发布、计划任务注册与唤醒。Linux 远端部署单元已提供。
